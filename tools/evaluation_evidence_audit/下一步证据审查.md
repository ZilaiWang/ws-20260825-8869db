# 当前结果的下一步证据审查

日期：2026-09-05。

## 范围

本文仅分析实验可信度、证据来源、软件测试与报告边界，不提供军事目标识别强化、目标筛选或部署优化实现。配套程序是独立、通用的离线元数据审计工具，不改现有项目代码。

## 目前能核实什么

本轮通过 GitHub 连接读取的公开 `main` 仍是 `ab51106949ad8369a5cccd862fcc19e1739cdeb2`。用户新贴出的实验回执没有同步为这个提交中的新结果。因此 54 项服务器测试、全量配对结果、三折结果与新耗时目前均属于用户提供的实验记录，不是本轮已在服务器独立复核的结果。

公开报告 `reports/experiments/HERA_GUARD_ATTEMPT4_DEEP_DIAGNOSIS_20260905.md` 仍明确区分短 OOF 与全量成熟训练血缘。发现三个名为 P40 的分折 checkpoint，不能单靠文件名消除这个区别。

上一版工具在真实集成路径中出现了用户回执所述的两个接口问题。此前 49 项局部测试没有覆盖这些真实路径；这不是已有测试数量能够抵消的问题。此前将正式基线的读出分支从代码默认值直接推定，也不够严格。应以当时实际发布资产和它们的输出为准。

## 一、必须区分三种“相同”

第一，两个实现处理同一输入后产生相同输出。

第二，新实验的控制实现与实际发布版本相同。

第三，实验中的训练过程与希望外推的最终训练过程具有可比性。

这三者互不替代。两种新实现各自完成 parity，只证明其相对参考实现一致，不自动证明参考实现就是发布基线。训练集回放相同，也不等于未见来源上相同。

审查材料应保留：参考版本、代码提交、容器 digest、权重 SHA、配置 SHA、依赖版本、输入文件/像素指纹、输出指纹、比较器版本、比较范围。缺少其中某一关键资产时，结论写“未确认”，不写“已经复现”。

## 二、P40 三折的两个问题必须分别回答

问题 A：每折模型是否真正未接触被评估来源？

问题 B：每折模型的完整训练过程是否与全量正式模型可比？

来源隔离可以成立，训练成熟度仍可能不同。应从父 checkpoint 与训练日志追溯初始化、阶段顺序、轮数、优化器/EMA、增强日程、batch 和 BN 等元数据。找到了三个分折权重，只回答“资产存在”；没有自动回答问题 A/B。

不能把已有数据上的结果差异直接乘以一个比例再外推到正式成绩；也不能仅凭两个训练阶段最终文件同名就判定训练过程相同。

## 三、后验缩小适用范围仍然是模型选择

用户回执中的过程包含多次范围选择：先整体，再部分组，再更小子集，同时又参考 full-seen 的变化。这个过程具有工程动机，但其后得到的“三折均正”应称为开发结果。

即使阈值是在另外两折上确定，只要最终使用哪些子集是在看完三折结果后确定，最终过程仍然使用了这些结果。阈值交叉拟合不会自动覆盖类别范围、分支所有权、采用/拒绝 full-seen 方案等更高层决策。

已经查看的来源可以继续作为开发诊断，但重新命名、重新分折、追加 bootstrap 不能恢复未被查看的状态。若没有未接触数据，就如实保留“经开发选择的结果”这一限制，而不是要求临时制造一个名义新确认集。

## 四、普通 OOF 与完整两层独立性不同

通用例子：数据分 A/B/C。模型 M_A 用 B+C 训练并预测 A。另一模型 M_B 用 A+C 训练，产生 B 上的校准预测。

若程序在 B 上使用 M_B 的预测选择参数，随后在 A 上评估 M_A，虽然 A 的直接预测模型未用 A 训练，但参数选择依赖的 M_B 接触过 A。

依赖图是：最终程序 → 参数选择 → 校准预测 → M_B → A。

这不是说所有 OOF 后处理都没有价值，而是说“直接模型没见过评估样本”不足以证明整条多阶段过程满足严格嵌套独立性。教师、伪标签、预处理统计与人工方案选择同样需要纳入依赖图。

配套工具专门提供了这个间接接触的合成示例，不会自动修正或重训任何模型。

## 五、三个正数不是三次完全独立成功

交叉验证的训练集合存在重叠，折结果会相关。不能把三个正差值当成三次独立伯努利试验，也不宜只用这三个数做普通 t 检验并宣称稳健。

应报告来源数量、每个来源的贡献、是否由很少的来源主导，以及结果是不是在方案选定前生成的。按来源组进行重采样可以描述已有数据上的条件不确定性，但不能修复后验选择，不能生成新的域，也不能证明隐藏数据上的收益。

非线性指标要先根据其定义汇总必要统计量，再计算指标；不能不加说明地平均每图得分来替代全数据指标。重复采样的来源需要按重数计入统计，不能先复制 ID 再被字典去重。此工具不计算这些性能指标，也不根据这些数字选方案。

## 六、测试分支比测试数量重要

回执中的连续图测试覆盖了一个容易路径，没有覆盖需要继续处理的困难分支。它足以证明“这些输入上输出一致”，不能证明“全部路径都通过”。

应将已有测试报告按普通路径、回退路径、空输入、边界值、批处理尾部、异常输入等实际分支分层。该分层是软件验证要求，不是增加或调整算法决策规则。

同时区分：局部函数耗时、整个程序耗时、一次运行和重复运行、冷启动与热运行。局部耗时下降某比例，不等于端到端也下降同样比例。本工具只接受覆盖元数据，不执行性能优化。

## 七、两个相同命令的展示不是两个进程的证据

用户回执末尾同一 SSH 命令出现两次。这可能只是界面重复展示，也可能是重复任务。不要据此直接判断异常。

应核对现有任务的 run ID、进程记录和输出写入者。如果两个任务写同一文件，完整性和计时解释都会受影响。新增审计只读已完成资产，报告使用独立路径，不覆盖正在生成的结果，不修改原有工作区。

## 八、增加服务器不增加数据独立性

独立的代码复现、血缘审查、报告整理可以并行；同一批来源上的方法搜索变多，不会让数据更独立。并行工作应对应不同检查问题，并保持各自输出隔离。

在截止前，最有价值的审查产物不是更长的候选名表，而是一个清楚记录“哪些已证实、哪些只在开发集成立、哪些还不确定”的证据包。不要用“最好一行”代替所有尝试的台账，不要在未完成资产生成时启动重复任务。
