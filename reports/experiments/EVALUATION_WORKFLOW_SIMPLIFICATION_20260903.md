本轮已修复负图读取、统一趋势比较入口并更新规范；没有启动训练，也没有宣称新划分已验证有效。

## 2. 反例：旧严格规则和“分数是否提升”并不等价

### 正式v1→v2

正式从72.1331增至76.6010，三硬门从FDR失败变为全通过，但三类Recall全部下降。
若机械套“每类Recall不得下降0.5pp”，这个已经实现的+4.468分会被拒绝。
这不表示所有历史被拒方法都值得重新训练，也不授权反写历史；只说明旧逻辑不是得分目标。

### 本地P20→P40历史回放

本轮直接读取两个冻结大图结果的 `primary.platform`，没有重新推理、拟合或选点：

|历史固定测试|质量子分对总分的贡献变化|车辆Recall变化|车辆FDR变化|
|---|---:|---:|---:|
|Hard|+3.1571分|−0.5435pp|−13.9620pp|
|Sentinel-B|+1.4435分|−3.7037pp|−5.8427pp|

旧的每类Recall≤0.5pp降幅约束会否决这两个点，但车辆自己的净计分贡献仍为正。
原平台payload没有绑定时延，本次重放只报告六项质量贡献之和/7，不借用不明口径耗时
补齐综合分。机器输入、输出见 [paired_trend_audit_20260903](paired_trend_audit_20260903/hard_comparison.json)，
另一项见 [sentinel_comparison.json](paired_trend_audit_20260903/sentinel_comparison.json)。

这些是回顾性检查，并不证明新划分已经能预测官方趋势。当前只有两次正式提交，无法给出
“趋势命中率90%”或“本地94线上至少92”的可信保证。

## 3. 新默认流程：尽量把算力用在候选上

```text
一次性：固定来源分组 → 训练/开发校准/确认三部分 → 缓存成熟基线与低阈值预测
日常：一个候选 → 开发区配对比较 → 明显正向才看确认区
交付前：固定大图/真负图/入口一致性/时延回归 → 用户决定是否full及提交
```

“三部分”不是三折训练：基线和每个候选只训练**一个模型**，同一个模型用于开发和确认。
开发与确认均不在这个模型及其初始化资产的训练来源内。不要用已见过确认源图的full权重
冒充这个模型。确认出现问题时先分析，不自动再排三个训练。

|保留|用途|不再承担的职责|
|---|---|---|
|固定配对验证|比较分数升降、逐类得失；开发选工作点、确认只应用|不拟合官方隐藏图组成，不每次改样本|
|部署回归|真负图FP、大图漏检、切片融合、接口、速度/显存|含同源数据时不声称独立精度或官方分数预估|

默认取消：每候选三折训练、Normal/Hard/Sentinel三张必过分数榜、四档FDR全部准入、
每次MacroRisk/bootstrap完整扫描、未经验证的“与官方绝对分差≤2%”承诺。
保留但按需：若增益由极少数车辆/稀有舰船支撑，做一次组级敏感性或定向读图；
若相反趋势无法解释，才考虑额外划分/训练，不重新启动整个历史链。

在训练配置相同且基线已缓存时，一个候选由3次训练降为1次，**训练工作量理论上减少约2/3**；
这是次数与工作量估计，不是已实测的墙钟加速保证。初始化基线成本单独记录，不藏进候选耗时。

## 4. 固定集需要怎样准备，现有资产不能怎样偷用

现有CV3分组数为fold0/1/2：82/95/78；图片数1507/1613/1361。GT实际支持：

|细类|fold0框/来源组|fold1框/来源组|fold2框/来源组|
|---|---:|---:|---:|
|HM（0）|6 / 3|6 / 4|5 / 4|
|LQS（1）|10 / 5|10 / 5|10 / 5|
|TU-160（9）|352 / 1|8 / 1|1 / 1|
|FSC（24）|133 / 7|134 / 7|135 / 7|

因此直接把fold0或fold1再按来源分成开发/确认，并要求两边都有25类，在TU-160上就不可行。
不能通过拆同机场组来假装独立，也不能给缺类默认Recall=1后当成完整正式分。

下一次训练前的一次性准备：

1. 在已有255个来源组上，以标签覆盖和训练支持而非候选得分决定新的单划分；
   大体按训练/开发/确认约70/15/15预算，**比例服从完整组与稀有类支持，不是已冻结样本数**。
2. TU-160只有三个组，无法创造更多独立证据；优先保留大组训练，另外两个组留开发/确认
   会导致确认支持极小，必须把该类波动显式标注，不能假装很稳。若全25类支持约束不可行，
   应报告不可行，不按框随机拆分补齐。
3. 真负图来源清单与标签审核必须进入回归资产；旧Background-100MP已有使用历史，属于
   已知压力测试，不宣称全新盲集。正式数据未知，绝不因本次车辆21%而调负图比例恰好凑21%。
4. 新分组只能改变未来实验的协议，不覆盖旧CV3或已提交模型；旧资产继续可追溯。
5. 缓存一个训练成熟度与拟议full配方对应的基线。以后优先从该基线做短适配/消融；
   从头训练新架构的40e结果只作筛选，不能将未收敛失败当理论上限。

**本轮未物化这些新划分，也未训练新基线。** 为了避免继续把流程越做越多，当前只完成
必要漏洞修复和报告统一；数据冻结是下一次GPU工作前的一次性基础工作，不是每候选新增步骤。

## 5. 阈值和判定怎样简化

### 一个开发目标

按平台公式最大化综合分，不再把FDR15当通用最优。
同一模型的延迟不随离线阈值重放改变时，可直接最大化六个质量子分和。
现有 `build_threshold_curve()` 已用一条官方匹配轨迹生成曲线，不需要每个阈值重跑模型。
默认沿用0.005开发网格，单个冻结工作点；没有明确边界证据，不增加细网格和25类搜索。

不同模型可选不同阈值，但必须按同一个开发规则，且用该模型自身预测校准。
同阈值回放只作辅助诊断：分数标度改变时，同数值阈值不是唯一公平对照。
确认区只应用开发工作点；既有部署阈值也不因为确认结果不好而现场修调。

### 一个主判断

以“候选−基线”的综合分为主，逐类得分贡献解释原因。
预先固定±0.5分为工程观察带：明显正向才确认，小变化或反向不自动加长训练。
0.5不是置信区间；少数来源或几个框决定符号时标记不确定，优先一次敏感性分析。
不因某一指标微降自动拒绝有利取舍，也不因为总分微升忽略总体Recall过线余量。

开发和确认明显同向，且回归没有关键问题，才讨论交付；方向冲突先停在分析阶段。
不能要求一个刻意留域验证上的低Recall绝对值先达到85%才允许任何研究，否则成熟full
与弱折内模型差异又会变成永久门禁。正式门槛与本地趋势证据分开记录，不伪造正式达标。

## 7. 怎样知道精简后真的更好

每次正式提交前只登记三件事：预期总分方向、主要受益/受损类别、证据是否独立。
正式回传后对照，不改写原预测；分别累计总分方向与逐类方向是否吻合。
允许本地绝对分偏高或偏低，但不允许因结果不符就重挑一个测试集后宣布命中。
若后续多次总分趋势仍不符，优先修正数据/训练成熟度，而不是再增加一层复杂门禁。
