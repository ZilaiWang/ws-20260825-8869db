# HERA-Guard v2：94% Recall 集成执行与证据报告

更新：2026-08-29
状态：`active_overall_gate_passed_budgeted_pixel_router_admitted`
目标：在严格来源隔离和接近官方的 10K 代理评估上，提高三大类 Recall，同时控制
FDR；不以同域 pooled 数字代替正式分项指标。

## 1. 目标口径

“Recall 超过 94%”必须拆成四层，不允许混用：

1. **候选上限**：在不设最终阈值时，至少存在一个同细类、达到官方 IoU 的候选；
2. **风险前沿**：只用 held-out 模型产生候选、只用其他 fold 选工作点；
3. **官方近似域**：在类别更均衡、六张互不重复来源的 trial-mix 10K 拼图复验；
4. **分项与时延**：舰船、飞机、车辆分别报告 Recall/FDR，3090 端到端不超过 20 秒。

当前阶段的准入目标为：

| 层级 | 主目标 | 防止误判的附加条件 |
|---|---:|---|
| 候选形成 | pooled Recall ≥ 0.97 | 舰船、车辆候选 Recall 均 ≥ 0.90 |
| 正式 OOF 风险前沿 | pooled Recall ≥ 0.94 | FDR 尽量 ≤ 0.15，完整报告 macro 和三大类 |
| trial-mix | pooled Recall ≥ 0.90，向 0.94 推进 | fold-heldout；不得用全量拟合权重回评 |
| 正式部署 | 三大类均通过官方硬门槛 | 3090 平均时延 ≤ 20 秒 |

94% pooled Recall 是模型集成的进度指标，不等同于官方七项排名全部达到 94%。

## 2. 上游证据回顾

### 2.1 已确认的能力

- P0-1/P0-2 证明对象 crop 后具有足够 token 可见性，并冻结了无来源泄漏的对象清单；
- P03 的 tight-224 ConvNeXt-Tiny 完整微调达到约 0.97 macro Recall，说明对象已被
  正确提取时，25 细类本身高度可分；
- P04 中 DINOv2-B CLS+patch 是最强冻结教师特征，但 CleanDIFT 单独线性探测弱于
  判别式教师，扩散特征不能替代主检测证据；
- Y5 的离散 90° 旋转增强稳定优于 M1；P2、FRACAL 空间项、单独背景门、简单 TTA
  支持惩罚等路线未形成足够独立收益；
- M3 RT-DETR-L 与 Y5 的架构差异产生强互补：正式对象配对中 M3-only 为 1,313，
  Y5-only 为 45，both 为 19,457，neither 为 118。车辆和微小目标受益最大。

### 2.2 官方预测评给出的域外警告

工程镜像 M1-fold0 的官方预测评结果为：舰船 Recall 0.8457、飞机 0.8069、车辆
0.5101，平均推理 2.33 秒。Docker、类别表、坐标和速度已通过，但训练集构成与预测
评数据差异明显，且临时 fold0 模型不是最终模型。详见
[`改进方案8.md`](../../../改进方案8.md) 和
[`MODEL_AND_WEIGHT_FREEZE_AUDIT_20260829.md`](../submission/MODEL_AND_WEIGHT_FREEZE_AUDIT_20260829.md)。

因此，本阶段新增 trial-mix：六张 10K 图、600 张唯一来源图、2,158 个 GT，粗类比例
约为舰船 44.2%、飞机 47.3%、车辆 8.5%。它比飞机占 85.3% 的正式训练 OOF 更能暴露
舰船/车辆缺陷，但仍只是内部代理，不是官方隐藏集。

### 3.1 候选形成

3. 单独背景门、800/1024 混合尺度、TTA 支持惩罚和简单三大类阈值均已作为负向

## 4. Y5 + M3 异构融合的正式 OOF 结果

### 4.1 单模型原始分数前沿

| 模型 | Recall@FDR≈0.10 | Recall@FDR≈0.15 | Recall@FDR≈0.20 |
|---|---:|---:|---:|
| Y5 | 0.8981 | 0.9171 | 0.9302 |
| M3 | **0.9129** | **0.9288** | **0.9378** |

M3 在全部固定风险点严格优于 Y5，且低阈值候选 Recall 更高。这与对象级 M3-only
证据一致，M3 不再只是“门控备选”，而是当前首要异构主干。

### 4.2 可部署标量 OER

输入只含部署时可观测变量：模型身份、模型分数、bbox 尺度/长宽比、每图候选密度，
以及另一模型的同细类/同大类 IoU 和分数。禁止使用 GT 派生特征和图像标签。三份
held-out 模型严格按正式 CV3 group 分离训练。

| 变体 | pooled Recall / FDR @目标0.12 | pooled Recall / FDR @目标0.15 | macro Recall / FDR @目标0.15 |
|---|---:|---:|---:|
| score+model | 0.9353 / 0.1232 | 0.9443 / 0.1517 | 0.9083 / 0.1797 |
| +geometry | 0.9382 / 0.1212 | 0.9477 / 0.1527 | 0.9113 / 0.1895 |
| +cross-model agreement | **0.9417 / 0.1249** | **0.9504 / 0.1532** | **0.9180 / 0.1788** |

这是当前第一次在合法三折交叉拟合下把 pooled Recall 推过 0.95。交叉模型 agreement
相对 score-only 在 0.15 风险点提高约 0.60 个百分点，证明异构一致性有独立价值。

但必须同时记录：

- 目标 FDR=0.15 在 held-out 聚合后变为 0.1532，存在约 0.32pp 校准漂移；
- 该点舰船 Recall/FDR 约 0.8710/0.2848；
- 飞机约 0.9666/0.1169；
- 车辆约 0.7587/0.5573；
- pooled 95% 由数量占优、表现最好的飞机主导，尚未解决官方分项短板。

按三大类分别在另外两折选择阈值也没有解决这一问题。在“每类 FDR 目标 0.15”时，
stitched held-out 结果为 pooled Recall/FDR 0.9415/0.1522；舰船
0.8013/0.1523、飞机 0.9733/0.1524、车辆 0.4652/0.1343。车辆为了压住 FDR
丢失了大量 TP，因此该路线作为负向消融停止。结论不是“阈值还没调好”，而是现有
标量特征无法在车辆候选中同时分离 TP 与背景 FP；车辆需要更强候选质量或像素证据。

模型和审计结果位于
[`outputs/Y5-M3-MULTI-OER-CV3-V3`](../../outputs/Y5-M3-MULTI-OER-CV3-V3)。前两次
V1/V2 因 prediction trace 索引不连续被审计门禁拒绝，未用于任何结论；V3 通过了
逐 fold 官方前缀等价检查。

## 5. 当前运行中的决定性实验

### 5.1 M3 trial-mix held-out：已完成

每张 trial-mix 图只由其来源 fold 未参与训练的 M3 checkpoint 推理，1024 tile、256
overlap、safe fusion、候选地板 0.03。

| 指标 | M3 |
|---|---:|
| 候选上限 Recall | 0.9235 |
| 舰船 / 飞机 / 车辆候选 Recall | 0.9067 / 0.9725 / 0.7391 |
| Recall@FDR≈0.15 | 0.7850 / 0.1509 |
| Recall@FDR≈0.20 | 0.8142 / 0.1929 |

M3 单独在 trial-mix 上不足以跨过 0.94，但飞机和舰船候选仍很强，角色应保持为
异构补漏源。车辆候选 0.7391 再次证明小目标候选形成仍是独立短板。

### 5.2 Y5 + M3 正式风险头迁移到 trial-mix：失败

Y5 identity + M3 identity 在 0.50 同类 NMS 后的联合候选上限为 **0.9490**，其中
舰船 0.9245、飞机 0.9941、车辆 0.8261。联合候选首次在 trial-mix 上跨过 0.94，
但几乎没有排序损失余量。

直接应用在原始 crop OOF 上拟合的 agreement OER：

| trial-mix 内交叉阈值目标 | Recall / FDR |
|---|---:|
| 0.10 | 0.5422 / 0.1123 |
| 0.12 | 0.5862 / 0.1234 |
| 0.15 | 0.6603 / 0.1528 |
| 0.20 | 0.7428 / 0.2033 |

而把正式 OOF 阈值也一并原样迁移时，目标 0.15 点在 trial-mix 实际变为
Recall 0.8323 / FDR 0.3462。结论是：异构候选具有价值，但原图 crop 域学到的风险
分数和阈值均不能迁移到 10K tile 域。

当前正在运行严格 trial-domain 三折交叉风险头：每折只用另两折 pseudo-10K 候选与
GT 拟合，只给 held-out 折打分；额外 NMS 放宽为 0.70。该实验回答“只是域内
风险头问题”还是“候选本身仍不足”。

### 5.3 全量拟合

两台 3090 正在串行/并行拟合：

- Y5-S：全 4,481 图，160 fixed epochs；
- Y5-L：容量对照，全 4,481 图，160 fixed epochs；
- M3 RT-DETR-L：120 fixed epochs；在 Y5-S 完成并优先做短 trial-mix 检验后启动。

这些全量权重用于最终工程提交，不用于回评由同一 4,481 图构造的 pseudo-10K 科学
结论。Y5-L 是否部署必须由独立证据和 3090 时延决定，不能因参数更大自动入选。

### 5.4 多尺度、异构三源候选：候选层已过线

冻结三类 held-out 候选源：Y5 identity+90°、Y5 800 tile、M3 RT-DETR-L，统一在
同细类 NMS=0.70 后合并。结果为：

| 指标 | Recall |
|---|---:|
| pooled 候选地板 | **0.9713** |
| 舰船 / 飞机 / 车辆 | **0.9570 / 0.9961 / 0.9076** |
| 独立 GT 候选可见性诊断 | 0.9722 |

独立诊断的 60 个未获得正确细类候选的 GT 中，50 个是定位不足、9 个是细类失败、
1 个是粗类失败。候选形成已不再是 pooled 主瓶颈；剩余定位缺口集中于舰船 35 个和
车辆 15 个。

但三源原始分数在 FDR≈0.15 时仅为 Recall 0.7655。由此正式确认：当前最大缺口是
把 97.13% 的候选覆盖转化为低虚警输出，而不是继续无条件增加检测器。

### 5.5 双模型取舍

| 候选源 | candidate Recall | ship / aircraft / vehicle | Recall@FDR≈0.15 |
|---|---:|---:|---:|
| Y5 ROT + Y5 800 | 0.9551 | 0.9434 / 0.9843 / 0.8533 | 0.7238 |
| Y5 800 + M3 | **0.9671** | **0.9518 / 0.9971 / 0.8804** | **0.7655** |

M3 与 800 尺度专家的互补明显强于两个同族 Y5 视图；若最终时延只能容纳两个源，
优先保留 Y5 800 + M3。三源仍只作为候选上限和 verifier 训练池，不能直接部署。

### 5.6 NMS 灵敏度：0.60 为当前代理工作点

| 同细类 NMS | 候选 Recall | Recall@FDR≈0.15 |
|---:|---:|---:|
| 0.40 | 0.9476 | 0.7757 |
| 0.50 | 0.9601 | **0.7776** |
| **0.60** | **0.9690** | **0.7776** |
| 0.65 | 0.9708 | 0.7729 |
| 0.70 | 0.9713 | 0.7655 |

0.70 多保留约 0.22pp 候选 Recall，却使固定风险召回下降约 1.21pp；这部分是重复或
冲突候选造成的真实代价。0.60 在候选安全性和固定风险之间形成当前 Pareto 工作点。

### 5.7 P03 像素证据：方向有效，但通用 HGB 再拟合失败

在 Y5 ROT+M3 候选上，P03 固定几何融合把 FDR≈0.15 的 Recall 从约 0.766 提高到
**0.8072**，证明真实 crop 像素有独立价值。随后用 detector、几何、P03 概率等
15--17 个标量训练 fold-heldout HGB：

| 变体 | candidate Recall | Recall / FDR @目标0.15 |
|---|---:|---:|
| 保持检测类别 | 0.9643 | 0.7966 / 0.1598 |
| P03 同粗类双假设 | 0.9671 | 0.7892 / 0.1489 |

两者均未超过简单 P03 融合。只有六张 mosaic 的域内 HGB 无法稳定学习复杂风险边界，
因此停止继续增加标量 OER 特征。下一项实验改为直接在 proposal crop 上训练
**25 细类 + background** 开放集验证器，同时学习背景拒识和细类纠错；先使用
NMS=0.60 候选做三折 outer-pure 快筛。

### 5.8 safe fusion 等价加速：代码完成，真实 10K 待验收

M3 的历史 10K 测速中，模型前向约 8--10 秒，但旧 safe fusion 需要额外
34--49 秒。审查确认主要热点是对所有细类候选执行 Python 全对全比较。当前实现已
改为：

- 先按 25 个细类独立分组；
- 每个细类内建立精确空间网格，只比较具有正面积相交可能的框；
- anchor 顺序、非传递聚类、同 tile 不合并、canonical 选择和最终 NMS 合同均不变；
- 当任一合并阈值为 0 时自动回退全对全路径，保持边界语义。

随机 3,000 候选基准中，新旧输出逐框完全一致，耗时从 0.207 秒降至 0.033 秒，
约 **6.3 倍**；20 项 fusion/submission 测试通过。该数字只是合成微基准，尚不能
替代 3090 真实 10K 端到端测速。只有真实 M3 候选逐框 SHA 等价且总时延满足预算后，
这一优化才进入 Docker。

### 5.9 COPH 近官方域复验：单模型不替换，融合有明确独立增益

历史 E8 COPH 是从每折 Y5 last checkpoint 继续 40 epoch 的存在性正则模型；正式
CV3 与 sentinel 均曾观察到小幅 Recall 正收益，但此前没有在 trial-mix 上检验。
本轮先将三个原始 checkpoint 清洗为只含推理状态的资产，并分别在真实舰船、飞机、
车辆图上核对清洗前后逐框类别、分数和坐标完全一致，再执行严格 held-out 推理。

COPH 单模型在 FDR≈0.15 时为 Recall 0.7729 / FDR 0.1472，不能替换现有三源池；
候选 Recall 也只有 0.9425。但将 COPH 加入 Y5 ROT + Y5 800 + M3，并统一执行
同细类 NMS=0.60 后：

| 变体 | candidate Recall | ship / aircraft / vehicle candidate Recall | Recall / FDR @目标0.15 |
|---|---:|---:|---:|
| 三源 | 0.9690 | 0.9518 / 0.9961 / 0.9076 | 0.7776 / 0.1499 |
| **三源 + COPH** | **0.9731** | **0.9570 / 0.9971 / 0.9239** | **0.8035 / 0.1492** |

融合净增益为固定风险 Recall **+2.60pp**，车辆候选 Recall **+1.63pp**。因此
COPH 的正确角色是互补候选源，而不是单模型替代。已新增全量 COPH 固定续训入口：
从全量 Y5-S 第 160 epoch 的原始 last checkpoint 继续 40 epoch，使用全部 4,481
图、无验证选模、只部署固定第 40 epoch。

### 5.10 开放集 proposal verifier：tight 训练/推理一致性获得正增益

NMS=0.60 的三源 proposal 训练 25 细类 + background ConvNeXt-Tiny；每个 held-out
fold 的模型只使用另外两折 proposal，P03 checkpoint 仅作为同折合法初始化。最初
context=1.25 直接融合在目标 FDR=0.15 时只有 Recall 0.7331，失败。随后按 P03 的
预注册证据，把训练 manifest 与推理 crop 同时改为 tight=1.0；不是只在推理时偷换
视野。tight 模型三折 checkpoint SHA 均与 context 模型不同。

随后仅用 detector、几何、开放集前景概率与 25 类条件概率训练 outer-fold HGB：

| tight 像素风险变体 | candidate Recall | Recall / FDR @目标0.15 | Recall / FDR @目标0.20 |
|---|---:|---:|---:|
| **保持检测类别** | 0.9690 | **0.8378 / 0.1492** | 0.8633 / 0.1997 |
| 同粗类双假设 | **0.9717** | 0.8285 / 0.1498 | **0.8665 / 0.1940** |

tight identity 相对三源原始分数提高约 **6.02pp**，相对 P03 固定融合提高约
**3.06pp**，证明“显式 background + 细类像素证据”有独立价值。双假设只在较宽松
风险点略有价值，因此默认保持检测细类，避免无保护 relabel。

### 5.11 三大类独立阈值：只保留为小型校准，不作为主解

为排查不同粗类分数尺度，新增三阈值联合优化：每个 held-out fold 的 ship、aircraft、
vehicle 阈值只用另两折联合选择，在 pooled FDR 约束下最大化 TP。三源池从
0.7776 提高到 0.7892，但实际 FDR 漂至 0.1561；三源+COPH 从 0.8035 提高到
0.8170，实际 FDR 漂至 0.1577，车辆仍不稳定。该结果与历史负向消融一致：分数
尺度失衡存在，但缺少像素可分性时，阈值本身不能解决车辆/舰船风险。

### 5.12 四源候选 + tight verifier：当前最强固定风险结果

将 COPH 加入候选池后，不重新使用隐藏折标签，不改变 tight checkpoint；仅对新的
46,566 个 fold-heldout 候选执行相同像素验证。四源候选 Recall 为 0.9731，三种解析
方式结果如下：

| 解析方式 | candidate Recall | Recall / FDR @目标0.15 | Recall / FDR @目标0.20 |
|---|---:|---:|---:|
| 直接 open-set 融合 | 0.9731 | 0.8499 / 0.1470 | 0.8740 / 0.1978 |
| **identity 像素风险头** | 0.9731 | **0.8601 / 0.1478** | **0.8791 / 0.1982** |
| 同粗类双假设 | 0.9754 | 0.8582 / 0.1508 | 0.8791 / 0.1996 |

identity 相对四源原始分数的 0.8035 提高 **5.65pp**，相对三源 tight identity 的
0.8378 再提高 **2.22pp**。在 FDR≤0.20 的接近官方代理口径下，整体 Recall 已超过
85% 硬门槛；但分项仍不均衡：目标0.15时 ship/aircraft/vehicle Recall 分别为
0.7914/0.9863/0.5163。因此当前结论是“总体门槛通过、飞机接近饱和、舰船和车辆仍是
正式排名风险”，不能宣称三大类均达到 94%。

### 5.13 预算化 tight 路由：1024 个/图是当前 Pareto 点

全量 tight 复核在 3090 上处理 46,566 个候选耗时 365.2 秒，即每张 pseudo-10K
约 60.9 秒，不能部署。新增 metadata-only fold-heldout router，只观察 detector
score、候选来源、粗/细类、框几何、图内密度与排名；每图选择最靠近风险工作点的
候选执行像素复核，其余使用廉价风险分数。

| 每张 10K 像素复核预算 | 预计像素耗时/图 | Recall / FDR @目标0.15 | Recall / FDR @目标0.20 |
|---:|---:|---:|---:|
| 0 | 0.0s | 0.7850 / 0.1487 | 0.8272 / 0.2003 |
| 256 | 2.0s | 0.8211 / 0.1468 | 0.8582 / 0.1958 |
| 512 | 4.0s | 0.8438 / 0.1467 | 0.8689 / 0.1980 |
| **1024** | **8.0s** | **0.8531 / 0.1493** | **0.8716 / 0.1968** |
| 2048 | 16.1s | 0.8545 / 0.1471 | 0.8744 / 0.1980 |
| 全量 | 60.9s | 0.8601 / 0.1478 | 0.8791 / 0.1982 |

1024 预算保留了全量像素复核约 94% 的净增益，只损失 0.70pp Recall；2048 相比
1024 仅增加 0.14pp，却增加约 8 秒。因此部署阶段只保留 512/1024 两档做真实端到端
测速。表中时延只含像素网络，必须再加 detector、切片、融合和 JSON 时间。

### 5.14 粗类分数专家：有互补，但必须留校准缓冲

direct open-set 对车辆更强，identity 风险头对舰船更强。固定采用 ship/aircraft=
identity、vehicle=direct 时，单一全局阈值因分数尺度不同而失败；加入 fold-heldout
三粗类阈值后，目标 FDR=0.12 得到 Recall 0.8550 / FDR 0.1185，比统一 identity
在同风险点提高 1.35pp。目标0.15虽达到 Recall 0.8684，但实际 FDR 漂到0.1540。
因此专家组合仅作为探索性正结果；正式工作点至少留2--3pp FDR缓冲，优先验证四源
hard-negative 重训能否用统一风险头吸收该互补。

### 5.15 目标0.15工作点错误分解：主矛盾是背景排序，不是框精修

对四源+tight identity 在交叉阈值目标0.15的输出执行与官方 matcher 完全相同的
逐图、同细类、一对一匹配，再按固定优先级归因。守恒检查通过：官方 322 FP、302
FN 与分解总数逐项相等。

| 原因 | 数量 | 占对应错误比例 |
|---|---:|---:|
| FP_BG（未被重复/分类/定位规则解释的预测） | **248** | **77.0% FP** |
| FP_DUP | 47 | 14.6% FP |
| FP_LOC | 18 | 5.6% FP |
| FP_CLS | 9 | 2.8% FP |
| FN_MISS（工作阈值后无可归因预测） | **275** | **91.1% FN** |
| FN_LOC | 18 | 6.0% FN |
| FN_CLS | 9 | 3.0% FN |

分项上，ship 的 FP_BG/FN_MISS 为149/176，vehicle 为80/87；aircraft 仅19/12。
细类 3、2 与车辆 24 合计贡献 226/248 个 FP_BG 和259/275个 FN_MISS。尺寸上，
FN_MISS 主要是 small 165 与 tiny 65。这里的 FP_BG 是排除其他归因后的诊断名称，
不是对真实场景语义背景的人工确认。

因此当前 0.8601→0.94 的主要缺口是：在 ship/vehicle 的大量背景候选中保护低分
真实目标。分类和 near-threshold 定位合计最多解释27个 FN，不能承担主线增益；
P06 框修正暂不重新准入。下一项实验应优先改善 hard-negative 采样、粗类专用前景
证据和多模型一致性排序。

### 5.16 多源一致性证据：恢复合并时丢失的可部署信息

四源 NMS 保留了最终框，却把 Y5-ROT、Y5-800、M3、COPH 对同一位置的共同支持压缩
成一个胜出候选；现有像素风险头因此无法利用正式 OOF 已验证有效的异构 agreement。
新增无 GT 的确定性注释层，对每个候选记录四个来源的同细类最大 IoU、固定
IoU=0.50下支持分数、支持源数量和 Y5/M3 异构支持标志。随后仍按来源 fold 对风险头
做 outer-heldout 训练，不增加正式 detector 或 crop 前向成本。该项与粗类均衡背景
采样分别回答“来源一致性”和“负样本组成”两个单因素问题，结果不得混写。

实际候选中单源支持28,826个，双源8,930个，三源5,367个，四源3,443个；说明该
特征并非近常量。但加入风险头后，identity 在目标0.15仅为 Recall 0.8156 / FDR
0.1423，相比不使用来源支持的0.8601显著下降。原因是6张大图中来源支持分布随
fold/场景漂移，HGB把它学习成不稳定捷径。随后保留原像素分数，只用另两折估计
支持数有效率并执行一次固定贝叶斯odds校准；目标0.15仍只有0.8100/0.1045，表现为
过度保守并淘汰单源真目标。高容量和低容量两种协议均失败后，该分支不准入，也不
继续扫描支持IoU或先验强度。

### 5.17 粗类均衡负样本与NMS=0.50：只产生分项互补

四源 hard-negative 重训把每个 batch 的 background 从自然分布改为 ship/aircraft/
vehicle 等概率，其余合同不变。目标0.15下整体为 Recall 0.8587 / FDR 0.1461，较
自然旧工作点轻微下降0.14pp；但 vehicle Recall 从0.5163升到0.5489，ship/aircraft
略降。因此“全局替换为均衡采样”不准入；待四源自然重训完成后，只比较
ship/aircraft=自然、vehicle=均衡的粗类专家组合。

基于工作点47个FP_DUP，单独将像素链同细类NMS从0.60收紧到0.50：候选Recall从
0.9731降到0.9634；目标0.15 identity 从0.8601升到0.8638，vehicle从0.5163升到
0.6033，但ship从0.7914降到0.7799；目标0.20整体则由0.8791轻降到0.8777。
结论同样是分项互补而非全局胜出。正式若采用粗类NMS，必须保留ship=0.60并重新做
统一交叉风险校准，不能直接拼接两个不同HGB分数。

### 5.18 粗类 NMS 单点复验：不改变原始固定风险瓶颈

依据 5.17 的分项现象，仅预注册一个组合，而不继续扫描：ship 使用 0.60，aircraft
和 vehicle 使用 0.50；输入恢复为原始 detector score，并重新执行两折选阈值、一折
评估。该策略把 46,566 个候选压缩为 44,739 个，候选 Recall 从 0.9731 轻降至
0.9722；目标 FDR=0.15 的 Recall/FDR 为 **0.8035/0.1479**，与四源原始分数的
0.8035 等价。

因此，收紧 NMS 能改善已经重排后的重复框结构，却不能让低分 TP 与背景 FP 在原始
分数上分离。它不作为独立主模块；若后续与像素证据结合，必须重新生成统一分数并
做完整 cross-fit，不允许拼接不同工作点。

### 5.19 判别式教师恢复与粗类二分类器：冻结中的两条像素证据

错误分解显示 77% FP 为 FP_BG，且 ship/vehicle 占绝大多数。由此冻结两条互补、
可直接归因的像素实验：

1. 三个 coarse-specific ConvNeXt 二分类器分别学习 ship/aircraft/vehicle 的
   foreground/background；每个 held-out fold 只使用另外两折 hard negative；
2. 恢复 P04 中最强冻结教师 DINOv2-B 的 1536D CLS+patch-mean 表征，在同一候选
   crop 上提取一次，并训练固定 epoch 的 fold-heldout 26 类线性开放集头。

DINO 资产重新按 P04 合同冻结：官方权重 346,378,731 bytes，SHA256
`0b8b82f85de91b424aded121c7e1dcc2b7bc6d0adeea651bf73a13307fad8c73`，官方仓库
commit `7764ea0f912e53c92e82eb78a2a1631e92725fc8`。此前汇总中只可靠记录了 SHA
前缀，本轮以实际官方文件完整哈希为准并保留资产锁。

所有新证据先使用固定对数几何平均直接融合；只有直接融合也改善，才准许作为可部署
增益。fold-heldout HGB 仅作为补充诊断，因为当前 crop 分数和 meta-risk 头尚未形成
完全 nested 的外层复验。DINO 不恢复 CleanDIFT：P04 中 DINO-B CLS+patch 的线性
探测为 0.9098，而 CleanDIFT 最强层仅 0.8293，重新运行扩散教师缺少性价比依据。

DINO 全量提取已完成：46,566×1536 fp16，341 秒，约136.6候选/秒。26类线性头
在 hard-negative 训练采样上达到约99%，但 held-out proposal 的细类准确率仅
65.3%--77.2%；使用 detector score 与 DINO 同细类概率固定融合后，目标0.15只有
Recall/FDR **0.5885/0.1494**，禁止使用 DINO 改类或直接提供同类分数。

另一方面，三个 held-out fold 的 DINO foreground/background AUC 为
0.9714/0.9741/0.9707，证明它仍包含独立前景信息。保持 detector 类别、只融合
`sqrt(detector_score × dino_foreground_probability)` 后，目标0.15为
**0.8401/0.1464**；再与 ConvNeXt 类概率等权融合为 **0.8193/0.1496**。两者都未
超过现有像素链，但车辆 Recall 分别达到0.5380和0.5924，表现为粗类互补。最后只
允许把 DINO foreground probability 作为统一风险头的一个新增特征复验一次；若
不能超过0.8601即关闭该分支，不扫描融合权重。

最终统一风险头结果为：identity 在目标0.15为 **0.8411/0.1467**，dual-hypothesis
为 **0.8262/0.1477**；目标0.20 identity 也只有0.8633/0.1889。全部低于既有
0.8601/0.1478，故触发停止条件：DINO proposal 分支关闭，不扫描融合权重、不进入
预算路由。其二分类 AUC 只保留为表征诊断，不作为部署收益。

### 5.20 防止代理集过拟合：独立 source-disjoint sentinel 合同

当前 trial-mix 只有六张 mosaic、600张唯一来源图，已被用于多轮候选与排序设计；
后续正增益不能继续只在同六张图上自证。构造器新增 `--exclude-ground-truth`：读取
开发 trial-mix 每张 mosaic 的 `source_images`，从三个 held-out fold 中剔除这600张
来源，再以新 seed 构造第二套6张/600来源的 trial-mix sentinel。构造审计同时冻结
排除输入 SHA、排除来源数、输出来源唯一性和 GT SHA。

sentinel 只复验已经在开发代理冻结的少数配置，不重新选融合权重、NMS或阈值公式。
若开发集增益不能在 sentinel 上保持同方向，则不进入官方提交。这项复验会增加四源
推理成本，但比在预测评平台重复排队更能降低五次正式提交机会的浪费。

### 5.21 下一候选：背景完整的检测器短程微调

官方训练4,481图没有纯背景；工作点又有248个 FP_BG。若 coarse binary 仍不足，
下一项不是再加 meta-feature，而是在另两折 pseudo-10K 中选择与任意 GT IoU≤0.10
的高分候选，围绕其生成1024 tile，并把 tile 内所有 GT 完整映射为 YOLO 标签。
held-out fold 的任何来源图禁止进入这些 tile。首个冻结构造为每张训练 mosaic 最多
160 tile、候选中心间距≥384px，既包含纯空背景，也允许“有其他正确目标但错误纹理
仍在”的困难场景。

该数据只用于从原 fold-heldout Y5-ROT checkpoint 做短程 fine-tune，再在未参与 tile
构造的 held-out pseudo mosaic 上评估。准入条件是固定风险 Recall 上升且候选 Recall
下降≤0.3pp；否则认为 detector objectness 被过度收紧并停止。该路线直接解决训练集
无背景这一结构缺口，也比对当前六张图继续调阈值更可能迁移到官方新背景。

### 5.22 背景完整检测器：执行合同已冻结

三折各构造640张1024 hard-background tile，候选中心与任意GT IoU≤0.10、中心间距
≥384px，且只使用另两折来源。fold0/1/2 的纯空tile分别为31/43/44；其余tile若包含
其他真目标，保留完整YOLO标签，避免把目标误教成背景。每折从对应Y5-ROT固定
checkpoint续训20 epoch，batch=8、无验证选点、只取固定last。准入仍为：held-out
trial-mix固定风险Recall上升，且候选Recall下降不超过0.3pp。

### 5.23 三大类检测到细类恢复：结构性单因素实验

P03已证明正确tight crop上的25细类macro Recall约0.97，而5.15显示当前主要错误是
ship/vehicle目标性和背景排序。由此新增一条不混入hard-background的单因素链：

1. 把训练标签由25细类确定性映射为ship/aircraft/vehicle三类；
2. 每折从对应Y5-ROT checkpoint迁移，固定30 epoch、无held-out选点；
3. 推理时将三类检测结果映射为0/4/24占位类别，使safe fusion仍按正确粗类工作；
4. 用同fold合法P03 checkpoint只在检测粗类内部恢复细类；
5. 固定沿用历史P03几何融合权重：detector 0.60、crop conditional 0.40，不扫描；
6. 先报告单源候选上限与固定风险前沿，只有正向才进入四源候选池。

这一实验检验“长尾细类检测头是否压低粗类目标召回”。若候选上限或固定风险不升，
则保持25类端到端检测；若只提升候选但排序较差，再由已有tight open-set verifier统一
解析，而不是为它另调阈值。

### 5.24 历史Y3只按“候选增强器”复验

Y3-HIER在原图OOF低阈值候选Recall约0.989，但因候选爆炸和少数细类分数塌陷被否决
为独立部署模型。当前已有显式proposal verifier后，重新审视它的唯一合理角色是补充
候选，而不是恢复Y3工作点。冻结复验为：在trial-mix上按held-out fold执行现有Y3
checkpoint，先报告单源前沿，再与当前四源NMS=0.60合并；若候选Recall净增不足
0.3pp立即停止，若净增明确才允许沿用同一tight verifier解析。不得重新训练Y3、不得
扫描其阈值，也不得以原图0.989替代10K结果。

### 5.25 分数感知 hard-negative：风险尾部的单因素复验

四源 tight proposal manifest 中共有31,003个明确背景候选、5,491个前景候选；其中
ship背景占24,960个。现有 coarse-specific 二分类器每模型只训练3 epoch × 40 batch，
每个epoch一半样本为负例，因而两折训练补集内大量背景从未进入梯度。均匀抽样还会
把容量消耗在几乎不可能跨过工作阈值的极低分背景上，而FDR实际由高分背景尾部决定。

冻结一个、不扫描强度的后续对照：网络、P03初始化、tight=1.0、三粗类拆分和训练
epoch均不变；负样本改为按 `sqrt(max(detector_score, 1e-4))` 加权抽样，同时把每
epoch batch由40增至80。前景仍按细类均衡且不按分数加权，以保护恰恰需要恢复的低分
真目标。该实验必须在均匀 coarse-binary 结果完成后才准入；只比较同一四源候选上的
固定风险前沿，不调融合权重。若目标FDR=0.15与0.20均无正向，立即关闭风险尾部采样
分支；若正向，再到source-disjoint sentinel按开发集冻结阈值复验。

### 5.26 三粗类阈值同集上界：校准已不是主缺口

为区分“跨粗类分数尺度失配”与“粗类内部不可分”，对当前四源+tight identity分数
额外计算一个**不可部署、只作诊断**的同集上界：允许直接使用全部trial-mix标签为
ship/aircraft/vehicle联合选择三个最佳阈值。目标FDR=0.15时得到1864 TP/327 FP，
即Recall **0.8638** / FDR 0.1492；目标FDR=0.20时得到1904 TP/474 FP，即Recall
**0.8823** / FDR 0.1993。对应的严格跨折结果分别仅为0.8568/0.1565与
0.8767/0.2040。

因此，即便赋予阈值选择不合法的同集标签优势，也无法接近0.94。当前0.8601到目标
的缺口不是靠继续扫描全局/粗类阈值能够获得；后续只保留背景完整检测训练、粗类目标
检测、proposal-domain视觉验证和候选互补四类结构实验，关闭进一步阈值工程。
