## 4. 根因分析

1. **候选输入质量是瓶颈**：对象学生 macro 0.7385 << GT crop 0.9287。
   学生从"质量差的候选 crop"学习，学到的是"M1 候选分布"，无法纠正
   M1 的细类错误——改写反而破坏原本正确的预测。
2. **M1 细类预测其实不差**：M1 的 FN_CLS 中，大部分是"候选存在但类别
   错"；对象学生复述候选类别 → 无法提供超出 M1 的信息。
3. **背景拒识有效但容量太小**：392 个背景候选只能带来 FP -89~98 的
   边际改善，杯水车薪。

## 5. 后续建议

1. **DINOv2-B 蒸馏（N2 第 6 步）**：P04-F 证明 DINOv2-B 表示最优（0.8294
   vs ConvNeXt 0.7815）。**但必须先修候选输入质量**——蒸馏不会解决
   "学生学的就是差候选"的根本问题。建议先验证 DINOv2 在 proposal crop
   上的表示质量（若 DINOv2 特征在差候选上仍强，才值得蒸馏）。
2. **候选质量提升优先于对象学生**：M1 的候选（尤其车辆 tiny/small，
   oracle recall 0.20-0.62）是硬瓶颈。**C 分工的小目标候选恢复优先级
   高于对象学生**——先让候选变好，再谈候选上的分类。
3. **困难门控暂缓**：对象学生未准入，门控（建立在学生分数上）没有意义。
4. **保持 M1 + cross-fit baseline 作为主线**：0.9176/0.1990 仍是当前
   最佳，N2 不改变主线。
