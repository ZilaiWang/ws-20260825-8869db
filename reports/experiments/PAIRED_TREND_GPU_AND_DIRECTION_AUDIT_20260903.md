## 2. 等待时完成的历史复核：方向对了一部分，原因没有对齐

“+6.212”、Sentinel“+2.214”与本表并不冲突。不得混用质量贡献差与综合分差。

进一步拆开净计分贡献（舰船 / 飞机 / 车辆）：

- 旧Hard：**+5.565 / −0.061 / +0.899**；

## 3. 这次如何检查新流程，而不事后挑一个能命中的测试

在foundation完成之前、尚未产生任何留出预测时，已经声明唯一比较对：

|端点|训练|推理|阈值|
|---|---|---|---|
|S1024参照|新训练区，官方初始化→160e|1024，当前统一YOLO入口|该模型自身开发区按官方质量分最大化|
|P40基线|上述同一个父权重→S1280适配40e|1280，同一入口|该模型自身开发区按同一规则选点|

两者分别把开发阈值原样用于确认；**不做确认oracle、不复制历史0.536、不按确认结果重选点**。
二者训练预算不相等：本轮检查的是既定160e与160+40e配方的实际升级方向，而不是证明
“只改分辨率”的单因素因果效果。不复刻历史中途迁移DDP和所有旧封装差异。

这是一次基准核验，预先声明两个端点都查看确认，即使开发不正向也保留反例；不把这个
例外开放给日常新候选。后续新方法仍按“开发>0.5才确认”执行。

输出的结论只有：

1. 开发的质量贡献差、确认的质量贡献差是否同向；
2. 是否与已知正式质量增益方向一致；
3. 六个R/FDR方向、三个类别净贡献是否一致，以及稀有细类TP/FP/FN；
4. P40基线的背景FP、接缝/入口逐框一致性和3090时延回归是否有问题。

即使全命中，也只是一次回顾性支持，不能称“趋势命中率100%”或承诺接下来三次都上涨。
若不一致，保留失败，不修改分组/阈值规则来追平官方。训练数据与官方隐藏集本来就不同；
主要目标是选出更有希望的方法，不是输出一个貌似精确的官方预计分。

## 4. 剩余三次机会怎样用

- 先建立这个固定参照，再让候选只改变声明因素；以后不默认重跑三折。
- 只有开发明显正向、确认同方向，且背景/部署没有重要反例，才讨论下一次正式候选。
- 分数优先、类别得失和硬门余量同时报告；不因为某类召回下降就自动否决净收益，也不因
  总分微升忽略当前正式Recall只高出门槛约1.248pp的事实。
- 正式提交前登记预期方向、主要受益类别及风险；回来后原样对账，不重写预测。
- 剩余次数不是必须用完。没有清晰证据，不把正式队列当阈值扫描器；当前v2资产保持可回退。

仍存在的限制：TU-160确认仅1框、HM仅2框；来源组是视觉代理；主评分区没有纯负图，
已审核382张背景只作独立压力指标。若增益由几个框决定，只作一次针对性的敏感性分析，
不再铺开多套榜单。**新A解决同模型开发→确认校准，但不能自动证明70%训练模型的阈值
可迁移到100%全量模型**；最终具体full权重和工作点的风险仍需单独说明。
