## 2. 七项总分的精确归因

官方总分为六个分类别分项与一个时延分的算术平均。Ship 两项完全不变；其余变化为：

|来源|七项原始分变化|折算总分变化|
|---|---:|---:|
|Aircraft Recall + FDR|`+1.2581 +0.9924 = +2.2505`|**+0.3215**|
|Vehicle Recall + FDR|`+0.7430 -4.2041 = -3.4611`|**-0.4944**|
|时延|`-3.4129`|**-0.4876**|
|Ship|0|0|
|合计|`-4.6235`|**-0.6605**|

所以失败机制没有歧义：Aircraft-D4 的收益是真实的，但被 Vehicle FDR 恶化和第二检测器
的时延代价共同覆盖。

若把 v3 的质量指标保持不变、只把时延恢复为 v2，复算约为 76.4281，仍比 v2 低
0.1729。也就是说，时延不是唯一原因；Vehicle 的质量净变化本身也抵消了飞机收益。

## 3. 哪些预期被官方验证，哪些被推翻

### 3.1 被验证：类别所有权与 Aircraft-D4

- Ship 的 TP/FP/FN 在两次提交中都为 `418/35/202`，六位小数指标完全一致。这证明
  P40 对 Ship 的结构旁路和 Docker 逐框所有权正确，没有隐性污染。
- Aircraft 从 `4711 TP / 168 FP / 231 FN` 变为 `4732 / 147 / 210`：净增 21 TP、
  减少 21 FP、减少 21 FN。D4 不仅方向正确，而且在正式隐藏集上同时提高 Recall、降低
  FDR。它是这次实验中唯一得到官方独立正证据的新模块。

### 3.2 被推翻：hierarchy Vehicle 在隐藏域的低风险泛化

Vehicle 从 `79 TP / 21 FP / 16 FN` 变为 `80 / 29 / 15`。召回只多 1 个目标，FP 却多
8 个；FDR 因样本只有 95 个 GT 而从 21.0% 跳到 26.61%。正式结果否定了“hierarchy
在 `t=0.420` 加 P40 高置信补漏后能在隐藏域同时提高 Vehicle Recall/FDR”的外推。

这份结果不能把 hierarchy 与 P40 rescue 的责任完全拆开，因为两者在同一次提交中启用；
但可以确定整个 Vehicle 组合不得继续作为正式主线。不能通过微调 0.420、0.600 或 0.700
在剩余两次机会中做隐藏集网格搜索。

### 3.3 已知而低估：第二检测器的排名成本

平均时延从 3.551833 秒增加到 6.964667 秒，增长 96.09%。它仍远低于 20 秒硬门，
但官方时延项在 0--20 秒内每增加 1 秒就损失 1 个原始时延分，即总分损失 `1/7`。
本次仅时延就损失 0.4876 总分。

此前验收偏重“低于 20 秒且稳定运行”，把硬门当成了优化目标。正确目标应是：新增模块
带来的六个质量分原始收益必须大于新增秒数。v3 新增质量原始分为 -1.2106，显然不可能
覆盖 3.4129 秒成本。

## 4. 内部代理为什么给出了过度乐观结论

### 4.1 关键工作点不是由独立 CV3 确认的

hierarchy 真正独立的三折结果是在 `expert_threshold=0.546` 下得到：CV3 质量贡献
`+1.9209`，Vehicle FDR -8.853pp，但 Recall -1.741pp。随后为了补 Recall，把阈值降到
0.420，并加入 P40 rescue；这个最终工作点只在 Hard/Sentinel-B 上选择，没有在未参与
选择的 outer fold 上再次确认。

因此“模型三折正向”与“提交工作点三折正向”并不是同一件事。我们错误地把 0.546 的
独立证据继承给了 0.420+rescue 的新策略。

### 4.2 full 权重代理含训练来源，只能验工程，不能验泛化

报告已经注明：full hierarchy、full D4 在 Hard/Sentinel-B 上的若干图像来源于正式训练
语料构造，full 模型见过这些来源。这些账本适合检查 full 物化、运行链和方向是否崩溃，
不适合作为隐藏域 FDR 准入证据。实际决策仍给了它们过高权重。

### 4.3 Vehicle 是小计数、高方差类别

官方 Vehicle 只有 95 个 GT。1 个 TP 对 Recall 约为 1.0526pp；8 个额外 FP 就足以使
FDR 增加 5.6055pp。Hard/Sentinel 中极低的 Vehicle FDR（约 3%--5%）没有覆盖官方隐藏
场景中的高分结构化背景。代理对 Recall 趋势尚有一点信息，对 FP 尾部分布明显失真。

### 4.4 绝对代理分不应作为官网分数预测

内部 100MP 压力分约 86 反映的是固定代理上的相对方向和硬门，不是官方隐藏分布。
代理集的目标密度、背景面积、来源构成和训练来源重叠都不同。把 `+4.61/+3.41` 的代理
质量增量机械平移到正式 76.601，是本轮最重要的推断错误。

## 5. 剩余两次机会的直接决策

### 5.1 首选候选：P40 + Aircraft-D4，彻底撤掉 hierarchy 与 Vehicle rescue

这是官方结果直接支持的最小改动：

- Ship 回到并保持 v2 的原输出；
- Vehicle 回到 v2 的 P40 原输出；
- 只保留已经在隐藏集证明 `+21 TP/-21 FP` 的 Aircraft-D4；
- 移除第二 YOLO 检测器，回收其主要时延成本。

以官方 v3 的 Aircraft 改善复算，D4 的原始质量收益为 2.2505 分。因此 P40+D4 相对 v2
能否净提升的判据非常清楚：**D4 单独增加的官网平均时延必须小于 2.2505 秒**。
下一步应先在 RTX 3090 的完整 Docker 上测 P40 与 P40+D4 的配对时延；满足该条件且
逐框旁路一致，再考虑第 4 次提交。

### 5.2 第五次机会：等第 4 次官方结果后再决定

- 若 P40+D4 高于 v2：以它为新主线；最后一次只接受无新模型、两套独立账本同向的
  Ship/Vehicle 小增量，或完全等价预测下的安全提速。
- 若 P40+D4 因时延仍不增分：比较 D4 identity/稀疏 D4 是否能保留大部分飞机收益并减少
  时延；不能则回到 v2，不为使用完名额而提交。
- 当前不再提交 hierarchy 阈值变体。正式隐藏反馈已经说明它的 Vehicle FP 尾部不可由
  现有代理可靠选择。

## 6. 评估流程立即修正

1. 模型、阈值、rescue 规则视为三个独立因素；任何一个变化都必须重新获得 outer-fold
   证据，不能继承父模型门禁。
2. full 训练来源派生的 Hard/Sentinel 只做工程与压力测试，不再承担科学准入。
3. Vehicle 报告必须同时给 TP/FP/FN 和基于小计数的最坏情景；不再只看百分比。
4. 准入目标从“过 20 秒硬门”改为“六个质量原始分增益 > 新增秒数”。
5. 两个固定测试保留，但候选选择只看相对趋势；最终工作点必须由来源隔离 CV3 冻结，
   压力集只能确认、不能选参数。
6. 一次官方提交最多包含一个尚未获得隐藏证据的模块。本次 Vehicle 模型、Vehicle 阈值、
   rescue 与 D4 同时进入，使失败后的因果拆分成本过高。

## 7. 当前结论

v3 不是“全部失败”：它给出了一个很干净的正式实验结论——Aircraft-D4 成功，Ship
旁路成功，hierarchy Vehicle 组合与双检测器部署失败。下一步不再扩实验树，先把已经由
官网验证的飞机收益从失败的 Vehicle/时延包袱中剥离出来，形成 P40+D4 单一候选。
