## 二、剩余误差的三维分解(核心)

当前工作点 Recall=0.9620 对应 **TP=20138, FP=2740**(FDR=0.1198)。

### 2.1 FP 分解

| 类型 | 数量 | 占比 | 性质 |
|---|---:|---:|---|
| **FP_BG(背景误检)** | **1899** | 69% | 位置无任何 GT 的背景框 |
| FP_CLS(细类错误) | 841 | 31% | 位置对但细类判错 |
| FP_DUP(重复框) | 0 | 0% | 已被 NMS 彻底压掉 |

### 2.2 candidate-floor 与排序损失

- candidate-floor = **0.9774**(理论上限: 改类后所有候选能匹配 20460 GT);
- frontier = 0.9620, 差距 = **322 个 GT 是"排序损失"**(有候选, 但候选分数不够高, 在 FDR=0.12 约束下够不到)。

### 2.3 三个杠杆

```
杠杆 1: 排序损失 322 GT  (有候选但检测器低自信)  → 需要更强排序或检测器训练

杠杆 3: FP_BG 1899       (背景误检)              → 需要新的正交背景证据
```

## 三、杠杆 1: 排序损失 322 GT(检测器低自信)

### 3.1 类分布(排序损失 GT 的主力)

| 类 | 数量 | 粗类 |
|---|---:|---|
| MS(导弹) | 83 | ship |
| QHS | 50 | ship |
| FSC(车辆) | 40 | vehicle |
| SU-35 | 27 | aircraft |
| TU-160 | 27 | aircraft |
| KC-135 | 18 | aircraft |
| F-16 | 15 | aircraft |

### 3.2 根因

- 这些 GT 的候选 **y5_score 极低**(真阳 y5_score<0.1 的类分布: MS 366 / QHS 222 / TU-160 190 / FSC 144 / KC-135 106);
- 检测器对这些类**本身低自信**(不是候选缺失——它们有候选, 只是分数低);
- y5_score 是 OER 的强特征(真阳中位 0.908 vs 背景 0.003), 低分真阳天然被背景 FP 挤下去。

### 3.3 解决路径

- **A. 检测器重训针对这些类**(MS/QHS/TU-160/FSC): 但 DFD(扩候选)已证伪, 需不同的训练策略(如 focal 加权的类平衡、或对这些类的专项增强);
- **B. OER 引入集合级证据**(DeepSets): 让"低分真阳 + 同图邻居证据"的候选被抬起来;
- **C. 接受为视觉上限**: 部分 MS/QHS 是极低对比目标。

## 四、杠杆 2: FP_CLS 841(兄弟机型混淆)

### 4.1 混淆矩阵(改类后仍错, 2171 个候选的 TOP 混淆对)

| 预测 → 真类 | 数量 |
|---|---:|
| **TU-22 → TU-160** | **347** |
| SU-35 → FA-18 | 199 |
| **MS → QHS** | **161** |
| **QHS → MS** | **127** |
| SU-35 → SU-34 | 119 |
| E-8 → KC-135 | 114 |
| FA-18 → TU-160 | 70 |
| SU-35 → F-15 | 65 |
| SU-35 → SU-24 | 63 |
| SU-34 → SU-35 | 59 |
| E-8 ← KC-135 | 59 |
| F-15 → F-16 / F-22 | 55 / 54 |

### 4.2 根因

- 混淆集中在**兄弟机型/舰船族**:
  - 轰炸机 TU-22 ↔ TU-160(347+);
  - 苏霍伊 SU-35/SU-34/SU-24(119+63+59+...);
  - 舰船 MS ↔ QHS(161+127);
  - 预警/加油 E-8 ↔ KC-135(114+59);
  - F 系列 F-15/F-16/F-22(65+55+54+...);
- **flat 25 类 softmax 无法区分兄弟机型**(翼型/垂尾/发动机布局等细粒度属性被扁平化);
- crop 教师(ConvNeXt-T)对这些兄弟机型能力有限(改类只救回 85%, 剩 15% 也错)。

### 4.3 解决路径

- **C 系列层次识别器**(方案4 §五.2 直接对应):
  - family(家族)→ fine(细类)→ attributes(属性) 三级;
  - 兄弟 hard-negative supervised contrastive;
  - 属性(翼型/垂尾数/发动机布局)只在俯视可见的选;
- 预期: 压 841 个 FP_CLS 的一部分, 同时可能救回部分排序损失 GT(细类纠错提升候选有效分数)。

## 五、杠杆 3: FP_BG 1899(背景误检)

### 5.1 根因

- **crop 教师对背景"幻觉"细类**: 39.5% 的背景候选 crop_top1>0.9(ConvNeXt-T 对背景 crop 也给出高置信的某类预测), 故 crop 证据无法压 FP_BG;
- 已用的背景证据: y5_score(强, 真阳 0.908 vs 背景 0.003)、has_oto(OTO 支持)、d4(旋转一致性);
- 剩余 1899 个 FP_BG 是"逃过 y5_score + has_oto + d4 三重过滤"的背景框。

### 5.2 解决路径(找新的正交背景证据)

| 候选证据 | 原理 | 成本 |
|---|---|---|
| ROI embedding(检测器内部特征) | 背景框的 ROI 特征与真阳可区分 | 需提取检测器中间特征 |
| scene-density token | 背景框在稀疏场景更可疑 | 需 P5 全局特征 |
| tile edge distance | 图边缘截断框可疑 | 轻量 |
| 上下文一致性(tight/context crop) | 背景框 tight 与 context 不一致 | 需 context crop 推理 |
| 更强的背景分类器(专训 BG vs FG) | 显式二分类背景 | 需训练 |

## 六、已证伪的方向(避免重复投入)

| 方向 | 结论 | 证据 |
|---|---|---|
| 扩候选(COPH 存在性正则) | 前沿 −0.62pp | A0 |
| 扩候选(DFD 密集前景监督) | floor +1.11pp 但前沿 −0.04pp | E9 |
| 去重(edge 聚类) | −2.4pp(FP_DUP 仅 0.4%) | E10 阶段1 |
| 小目标(P2/SAHI/2×放大) | 救 6/82 | E10 |
| 基础模型教师(DINOv2 等) | 网络受限 | A4 |

**核心教训**: 瓶颈从来不是候选缺失或去重, 而是"对象级联合裁决(OER)的排序质量 + 背景/细类的判别证据"。

## 七、"再拉高一档"的路径(按 ROI + 成本排序)

| 优先级 | 方向 | 针对性 | 成本 | 预期 |
|---|---|---|---|---|
| **P0** | C 系列层次识别器(家族+属性+兄弟 contrastive) | FP_CLS 841 + 部分排序损失 | 训练识别器(1 折级) | 混淆矩阵清楚, 方向最明确 |
| **P1** | 新背景证据(ROI embedding / scene token) | FP_BG 1899 | 需提取检测器中间特征 | 潜力最大但证据需验证 |
| **P2** | OER-v1 DeepSets(集合级聚合) | 排序损失 322 | 表格→集合模型 | 候选证据已足, 缺集合上下文 |
| **P3** | 检测器针对低自信类重训 | MS/QHS/TU-160/FSC 低自信 | 训练检测器 | 需规避 DFD 教训 |

### 我的判断

1. **C 系列层次识别器是 P0**: 混淆矩阵把兄弟机型混淆暴露得清清楚楚(TU-22↔TU-160 347、MS↔QHS 288), 这是唯一"根因清晰 + 方法明确"的方向;
2. **FP_BG 潜力最大但最难**: 1899 个背景框是最大头, 但 crop/d4/oto 都已用, 下一个证据维度(ROI embedding)需要动检测器内部;
3. **排序损失的 322 GT 与 FP_CLS 有交集**: MS/QHS 既是低自信(排序损失)又混淆(FP_CLS), 层次识别器可能同时改善两者。

## 八、供 GPT 讨论的关键问题

1. **C 系列层次识别器**: 家族树怎么定义(aircraft 20 类怎么分组族)? 属性监督哪些俯视可见? 兄弟 hard-negative 对比学习怎么构造?
2. **ROI embedding 作背景证据**: 检测器中间特征 vs 背景分类器的性价比? 有没有更轻的背景判别方式?
3. **检测器低自信类(MS/QHS/TU-160)**: DFD 已证"扩候选"无效, 那"提升这些类的检测自信"的正确训练策略是什么(类平衡? focal? 专项增强)?
4. **理论上限**: candidate-floor 0.9774 是否就是当前 Y5 检测器的天花板? 还是有方法突破?
