# 第 2 部分 已学到的关键教训(决定创新方向不能踩的坑)

## 2.1 Y3-HIER 失败解剖(层次损失——最接近"大改"但失败的案例)

Y3 在 M1 上加**层次粗细类损失**(粗类先验 + 细类残差),意图提升细类判别。结果:

| 观测 | 数据 |
|---|---|
| Recall 天花板 | 0.9891(比 Y5 还高!) |
| 候选量爆炸 | 622,257(11.2× M1)——层次损失让模型"什么都敢报" |
| 分数分布两极化 | 低分噪声堆 0-0.1(45.6 万),真阳尾巴拖到 0.35 以下 |
| 为达 FDR≤0.20 被迫用 t=0.7 | 少数类被系统性误杀:HM 0 / LQS 0 / TU-160 2.2% |
| Macro Recall | 0.745 vs M1 0.867(落后 12pp) |
| 细类错配 | FN_CLS 1,560 vs M1 1,115——**层次损失没改善细类** |

**失败根因(关键)**:粗类头先兜底、细类头后精修的两阶段损失,把**置信度分数校准破坏了**——模型对"粗类对但细类拿不准"的目标给出高置信粗类分。训练期任何结构改动若不做分数校准验证,再高的 Recall 天花板也无用。

**给创新设计的硬约束**:任何 YOLO 大改,必须验证 ①候选量不爆炸(相对基线 <2×)②TP 分数分布不两极化(TP<0.7 比例不显著上升)③少数类 recall 不塌陷。

## 2.2 Y5 成功的本质(为什么旋转增强有效)

- 90° 旋转增强**不改损失/结构**,只扩训练分布 → 分数校准与 M1 同源(候选量 1.18×);
- 效果:Recall 天花板 +4.3pp(0.9316→0.9741),工作点 Recall +0.4pp 且 FDR -4pp;
- **结论:当前瓶颈不是"模型能力上限",而是"校准 + 少数类 + 细类"的系统性工程**——这为"结构大改"留了空间,但必须保住校准。

## 2.3 M3 异构互补的价值(教师证据)

- RT-DETR-L(YOLO 之外的第二架构)找回 M1 漏检 1,313 个 hard positives(车辆 56 恰覆盖 C 的 Recall 0.85→0.90 门槛);
- 双漏 411 中 M3 能救 320 个(78%)——**架构多样性是补漏的最强杠杆**;
- 时延代价大(12.40s),引出门控推理问题(3.6)。

# 第 3 部分 未解问题深度解剖(按对最终指标的影响排序)

> 每个问题按统一模板:现象 → 硬数据 → 根因假设 → 为什么现有手段不够 → 对指标的具体影响 → 解决方向(供 GPT 深化)。

## 3.1 【卡主线】N2-CFG 背景门控:ship/vehicle 负样本不足(gate2 失败)

### 现象
为压 FDR 设计的前景/背景门控分类器(ForegroundGate,convnext-tiny 粗类条件头,在 M1 候选上二分类"前景 vs clear_background"),三折训练 loss 收敛良好(0.0085/0.0156/0.0119),但门禁 g2(按粗类的 FP_BG 删除率)失败。

### 硬数据(首跑全链路,2026-08-20 00:42-01:17)

| 门禁 | 结果 | 数值 |
|---|---|---|
| g1 pooled FP_BG reduction | ✅ | S2 删 186 vs S0 基线删 19,ratio 0.12≥0.10 |
| **g2 coarse reduction** | ❌ | **aircraft 0.3065(优秀)/ ship 0.0014(需≥0.15)/ vehicle 0.0259(需≥0.10)** |
| g3 fold consistency | ✅ | - |
| g4 source concentration | ✅ | max share 0.0968≤0.4 |
| g5 paired bootstrap | ✅ | delta=167,95%CI[117,228] 下界>0,2000 次显著 |
| g6 focus classes | 报数 | HM/LQS/TU-160 removed 0,F-22 removed 1 |
| g7 zero_tp_loss | ❌ | S2 应用误删 3 个 TP(recall_budget=0 不允许任何 TP 删除) |

各粗类明细:S2 删除率 = 删除的 FP_BG / 该类 FP_BG 总数:
- aircraft: 179/584 = 30.7% —— **门控真的有效**;
- ship: 1/723 = 0.14% —— 几乎没学;
- vehicle: 6/232 = 2.6% —— 几乎没学。

### 根因假设(已排除代码 bug,确诊为数据问题)
1. **白名单负样本太少**:人工确认的 clear_background 只有 33 个 proposal(ship 13 / aircraft 9 / vehicle 11),ship/vehicle 的粗类条件头没有足够样本来学"什么不是目标";
2. **类间可分性差异**:aircraft 背景(跑道/建筑/停机坪)与飞机视觉差异大,9 个样本就能学;ship/vehicle 背景与目标相似度高,13/11 个样本远不够;
3. 附带:g7 误删的 3 个 TP 全是 fold0 低分边界目标(score 0.012~0.038,q 值 0.005~0.029)——门控正确识别"低分背景",但 0 容忍门禁判失败。

### 为什么现有手段不够
- 扩审第 2 批(566 卡,ship 245 / vehicle 87 为主)已发学姐,回传后白名单约 98 个,ship/vehicle 负样本翻 3-4 倍——**大概率改善但只是"够用",不是"好"**;
- 本质问题:**FP_BG 是 M1 的分数低尾**(S0 基线用极低分数阈值已删 99% 的 FP_BG?——不,修正口径:S0 只删 1.2%,S2 删 12.1%),门控的增量空间有限,且**边界 TP 与低分背景高度重叠**(分数空间分不开,见 3.5)。

### 对指标的影响
- g2 过不了 → N2-CFG 不能进最终链 → FDR 卡在 0.157,压不到 0.12 目标;
- g7 的 3 个 TP 损失虽小,但暴露"门控与目标在低分区间重叠"这一更根本的问题。

### 解决方向(供设计)
1. **负样本工程**:把 FP_BG 池按分数段/粗类分层扩审(已在做);合成难负样本(把目标 crop 平移/旋转后当背景);
2. **门控目标函数重构**:从"二分类删不删"改为"软权重/残差校正"(保留边界 TP,压中高置信背景);
3. **把门控并入 YOLO 结构**:在 YOLO 的检测头旁加一个"背景抑制分支"(类似 DETR 的 no-object query),训练期端到端学,推理零额外成本——**这才是"大改"方向**,N2-CFG 是它的离线原型;
4. 门禁本身是否允许极小的 TP 预算(如 ≤3)做权衡——团队决策问题。

## 3.2 【Recall 天花板】三模型全漏 91 个目标(小目标为主)

### 现象
Y5 与 M1 双漏 411 个 GT(约占 GT 总数 2%),其中 M3 能救 320 个,真正**三个模型(Y5/M1/M3)全漏的只有 91 个**。

### 硬数据(91 个全漏的构成)

| 维度 | 构成 |
|---|---|
| 细类 | QHS 36 / FSC 20 / A17_TU-95 14 / MS 5 / A20_SU-24 3 / A10_B-1B 3 / A9_P-3C 2 / A1_SU-35 2 / LQS 2 / 其余 8 |
| 尺寸 | small 47 / tiny 26 / medium 18 —— **small+tiny 73 个(80%)** |
| 粗类 | ship 43 / aircraft 28 / vehicle 20 |

**QHS 36 个 + FSC 20 个 = 56 个(62%)集中在两类**——这不是随机噪声,是有明确模式的失败。QHS(海警船)疑似与码头/港口设施混淆,FSC(车辆,小目标)疑似淹没在道路/停车场纹理中。

### 根因假设
1. **小目标特征不足**:≤96px 的目标在 1280 输入下占像素极少,backbone 下采样 32 倍后只剩 1-3 个特征点;
2. **上下文混淆**:QHS 大概率靠"水边 + 船形"判别,若停在码头边或与其他船重叠则不可分;FSC 与道路车辆/集装箱卡车纹理相似;
3. **遮挡/极低对比度**:部分 GT 可能被树影/建筑阴影覆盖(需看图确认,尚未逐张人工看)。

### 为什么现有手段不够
- 旋转增强(Y5)、充分度采样(Y4)、层次损失(Y3)、异构架构(M3)四管齐下仍漏——说明是**特征分辨率/上下文层面的系统短板**,不是单点增强能补的;
- 91 个只占 0.43pp recall,但**它们是"最难样本",往往也是官方重点考察的"极端情况"**。

### 对指标的影响
- 候选层面 recall 上限:91 个全漏 = 0.43pp 的硬天花板(如果 Y5+M1+M3 全用且不引入新漏);
- 对 Macro 影响:QHS 36 个全漏 ≈ QHS recall -1.8pp。

### 解决方向(供设计)
1. **SAHI/切片推理**:把大图切成 512/640 子图分别检测再合并——对小目标有立竿见影的效果,代价是时延(需评估,20s 预算内);
2. **P2 高分辨率头**:在 YOLO 的 P2 层(1/4 分辨率)加检测头,专治 ≤64px 目标(现有 YOLO26s 是否已有 P2?需查配置——这是"大改"的自然切入点);
3. **失败案例驱动**:91 个全漏目标逐张可视化,归纳"哪些背景/上下文下必然失败",反推特征需求;
4. **上下文/场景建模**:QHS 36 个集中在港口站点(source_group 分析可验证),若加入"站点级先验"(某站点有港,则提升该区域 ship 灵敏度)可补——这需要把站点信息(已有 source_group 字段)用起来,是**独创性方向**。

## 3.3 【Macro/FDR】细类混淆:兄弟机型判别弱

### 现象

**关键读数**:
- 混淆对高度集中在**同粗类的"兄弟机型"**(TU-160/TU-22、SU-35/SU-34、KC-135/E-8、F-22/F-16/F-15)——语义学上这些机型确实长得像(同族气动布局);
- 混淆大多是**双向的**(TU-160↔TU-22 222+32;SU-35↔SU-34 140+126)——说明是特征可分性不足,不是单向偏差;
- **跨粗类混淆极少**(飞机↔舰船几乎没有)→ 粗类判别已解决,细类是瓶颈;
- **Y5 的混淆对与 M1 同源**(未重算 Y5 全量,但 FN_CLS 896 vs 1115 说明结构一致)→ 训练期增强/损失对细类判别帮助有限。

### 根因假设
1. 遥感俯视下兄弟机型(尤其俄系轰炸机 TU-160/TU-22)差异是**翼展比/尾翼构型/机鼻轮廓**这类细微几何特征,CNN 特征被背景纹理淹没;
2. 细类样本不均衡(见 0.3)放大:TU-160 只有 361 个 GT,而 F-16 有 1,017 个,模型偏向常见类;
3. 部分类之间在**官方 IoU 匹配语义**下本来就近(同一家族),需要属性级判别。

### 为什么现有手段不够
- 层次损失(Y3)专门想解决它,但**破坏了分数校准 + 细类头没有更细的监督信号**,FN_CLS 反而恶化到 1,560;
- 单纯数据增强(Y5)不动损失,细类判别保持基线水平;
- **需要"细类判别专用机制"**,而不是期望检测头隐式学出兄弟机型差异。

### 对指标的影响
- FP_CLS 896 是 FDR 0.157 的构成部分(FP 总量约 3,584),压掉一半 → FDR ≈ 0.12;
- FN_CLS 896 是 Recall 0.921 的漏损,修正一半 → Recall +2pp;
- **细类混淆是同时拉高 Recall 和拉低 FDR 的最大单一杠杆**,也是 Macro 的直接敌人。

### 解决方向(供设计)
1. **细类专用判别分支(大改核心候选)**:检测头输出 coarse logits + fine logits,但**分开优化**(coarse 用检测损失, fine 用独立的细类损失并只在 top-K 候选上算)——避免 Y3 的耦合破坏校准;
2. **混淆对后处理**:利用"同粗类 + 高 IoU + 兄弟机型"的先验,对 TU-160/TU-22、SU-35/SU-34 这类已知对做**成对重分类**(局部二分类,利用兄弟机型的细微差异特征);
3. **结构化属性监督**:手工属性(翼展比/发动机数/尾翼构型)作为辅助任务(多任务头),遥感俯视图可标注性强——**独创性高,适合竞赛加分**;
4. **细类校准**:每类独立阈值/温度(稀有类用更激进阈值),工作点层面直接修正 Macro;
5. **细类重采样/解耦**:把细类平衡嵌入采样(类似 Y4 但按细类而非图充分度)。

## 3.4 【Macro 杠杆】稀有类 HM(17 个)/LQS(30 个)不达标

### 现象
HM recall 0.647(11/17 对,6 漏)、LQS 0.600(18/30,12 漏)。已好于 M1(HM 0.706→其实 Y5 略降 / LQS 0.500→0.600),但距离"优秀"很远。

### 硬数据

| 类 | GT | Y5 tp/fn | Y5 recall | M1 recall | 尺寸中位 |
|---|---|---|---|---|---|
| HM | 17 | 11/6 | 0.647 | 0.706 | 249px(大) |
| LQS | 30 | 18/12 | 0.600 | 0.500 | 146px(中) |

**注意矛盾**:HM 是**最大的目标**(中位 249px,min 124px)——漏检 6 个不是因为"小",而是**稀有 + 可能与其他船/码头重叠**;LQS 漏 12 个也可能与 MS/QHS 混淆(混淆矩阵里有 MS↔QHS,但 LQS 是否与 MS 混淆需查)。

### 根因假设
1. 17 个训练样本(三折后每折训练集约 11 个)不足以学到稳健特征;
2. 大目标在 1280 输入下可能被**切片/下采样后的多尺度锚点**漏掉(目标太大,单尺度检测头覆盖不佳);
3. 与 QHS/MS 共处港口时互相遮挡。

### 为什么现有手段不够
- 数据增强(Y5)提升有限(HM 反而略降——0.706→0.647 是 1 个样本的抖动,17 个样本的统计噪声很大);
- 重采样(Y4)对 ship 无帮助(LQS 0.500→0.300?不,Y4 LQS 是 0.300,Y5 是 0.600);
- **17/30 个样本,任何纯数据方法的天花板都很低**——需要"知识注入"。

### 对指标的影响
- **Macro 口径下,HM 从 0.647→0.85 = 直接 +0.2 分(25 类平均里 1 类)**,是所有单类改动中 Macro 杠杆最大的;
- LQS 0.600→0.75 = 再 +0.15 分。

### 解决方向(供设计)
1. **原型/度量学习**:用大类内共享特征做"舰船原型",HM/LQS 从原型微调(少样本学习范式——**契合"小样本"赛题,独创性高**);
2. **模板匹配/几何先验**:HM(海警船)有固定几何特征,可用先验模板增强检测头输出;
3. **数据合成**:把 MS/QHS 的舰船 crop 通过 HSV/光照/角度变换合成 HM/LQS 风格样本(需要类间差异是"可合成"的);
4. **细类级正样本挖掘**:从全量候选里按"高置信 ship 但低细类置信"的样本做伪标注扩充训练集(半监督);
5. **跨类共享+细类残差**:HM/LQS 共享 ship 主干特征 + 细类残差头(注意 Y3 教训,要保校准)。

## 3.5 【校准】分数分布长尾:低分真阳与背景重叠(最隐蔽的系统问题)

### 现象
Y5 相比 M1,工作点只能从 0.05 抬到 0.1,就是因为**多了大量低分候选**;进一步压 FDR 到 0.12 时,低分真阳(尤其 TU-160/FSC)会被一起杀。

### 硬数据(三模型 TP 分数分布,官方匹配口径)

| 模型 | TP 数 | P10 | P50 | P90 | TP<0.3 | TP<0.5 | TP<0.7 |
|---|---|---|---|---|---|---|---|
| M1 | 19,502 | 0.736 | 0.896 | 0.922 | 3.9% | 5.8% | 8.9% |
| **Y5** | 20,391 | **0.179** | 0.908 | 0.938 | **11.5%** | **13.9%** | **17.5%** |
| Y3 | 20,703 | 0.347 | 1.000 | 1.000 | 9.2% | 13.9% | 16.5% |

**关键洞察**:
- Y5 比 M1 多找回的 889 个 TP 里,大量是**低分真阳**(P10 从 0.736 掉到 0.179,TP<0.5 从 5.8%→13.9%)——旋转增强让模型"敢报"但也"报不准";
- 这些低分真阳集中在哪些类?大概率是 TU-160(recall 0.371,均值附近低分)、FSC(小目标)和部分混淆类——**需要逐类验证(数据在 /tmp/Y5-full.json 可算)**;
- 后果:想压 FDR 到 0.12,必须在 t≈0.2 工作(见阈值曲线 t=0.2:FDR 0.117 但 Recall 掉到 0.9062)——**丢了 1.5pp recall**;
- N2-CFG g7 误删 3 个低分 TP,是同一现象的另一个面。

### 根因假设
1. 增强(Y5)与结构(Y3)都会引入"低置信但正确"的检测——模型对难样本(遮挡/小尺寸/稀有类)给低分是**合理的**,问题是后处理一刀切;
2. 目前后处理只有全局阈值 + NMS,没有"按类/按置信度形状"的差异化策略。

### 为什么现有手段不够
- 全局阈值无法同时满足"保住低分真阳"和"杀掉低分背景"——**两者在分数空间重叠**;
- 需要**二维判据**(分数 × 类 × 尺寸 × 上下文)而非一维阈值。

### 对指标的影响
- Recall 0.921→0.96 目标的关键路径:把工作点从 0.1 下移到 0.05 而不涨 FDR(即 0.05 处 Recall 0.9335 但 FDR 0.2035 超标 0.35pp——**只差一步!**);
- 如果 N2-CFG 门控能删掉 0.05 处多出的背景,Y5@0.05 就是完美工作点(0.9335/0.2035→删 5% 背景即达标 0.19x);
- **Y5@0.05 + 门控 = 直接 Recall +1.2pp 且 FDR 达标**——这是"融合现有组件"就能拿到的增量。

### 解决方向(供设计)
1. **门控/背景抑制作为分数校正器**(而非硬删):对候选输出"背景概率",重排分数而非删框;
2. **类内阈值 + 校准温度**:按类统计分数分布(数据都有),稀有类/难类用更低阈值,常见类用高阈值;
3. **尺寸-分数联合**:小目标允许低分(单独阈值),大目标必须高分(因为大目标低分多半是误检);
4. **训练期分数分布正则**:保校准的损失(如 Focal 的 γ 调低对难样本的压制)——与 3.3 的细类分支结合。

## 3.6 【时延预算】双模型组合已占 14.28s,门控推理 T4 悬而未决

### 现象与硬数据
- M1 本机 after-read 1.89s + M3 12.40s = 组合 14.28s(p95 14.46s),wall 16.88s ≤20s;
- 但若最终链 = Y5 + M1 + M3 + 切片推理(3.2 方向 1),时延会叠加:Y5≈M1(1.89)+M3(12.40)+ 切片(2-4×)→ 可能超 20s;
- T4-GATED-INFER 判定:TP 净增 1,268 ≥30 ✅ / gate5 p95 14.46≤18 ✅ / gate4(N2-CFG 后 FDR≤0.17)⏳。

### 矛盾
- 多模型融合补漏(3.2 的 M3 320 个)与时延预算冲突;
- 切片推理(小目标方向)与 20s 预算严重冲突(每图 4 切 = 4×1.89 = 7.6s 单 Y5,可接受;但 4×组合不可接受)。

### 解决方向(供设计)
1. **门控推理**:用 Y5 快筛出"低置信区域/低覆盖图",只对这些图/区域跑 M3(预期 20-40% 图触发,时延 14.28→8-10s);
2. **单模型化**:把 M3 的能力**蒸馏进 Y5**(见 3.7 方向 8),推理保持单模型 1.89s——**这是"大改"的终极形态**;
3. **切片只用于 FSC/小目标类**:按类分流(车辆类切片,YOLO 原生检测大目标),时延可控;
4. 预演已发现 wall 口径风险(历史 19.37s 逼近),正式 16.88s 已过,但要留余量。

## 3.7 【数据】官方 real_official 10K 图未提供 + 负样本人工审核瓶颈

### 现象

# 第 5 部分 给 GPT 的 YOLO 独创性大改方向弹药(含设计问题)

> 以下每个方向都附:证据、为什么值得、**关键设计问题(需要 GPT 深化/决策)**、预期收益、风险。
> 我们的约束:YOLO26s 基座 + 三折 OOF 可复现评估 + 20s 时延预算 + 不破坏分数校准。

## 5.1 背景抑制与检测一体化(把 N2-CFG 塞进 YOLO)

- **证据**:N2-CFG 离线门控对 aircraft 删 30.7% FP_BG 有效、paired bootstrap 显著(Δ167,CI[117,228]);但 ship/vehicle 负样本不足 + 边界 TP 误伤;
- **大改设想**:在 YOLO 检测头旁加"背景抑制分支"(类似 DETR 的 no-object query / 额外背景类 logit),训练期端到端,推理零额外成本;
- **设计问题**:背景分支的监督来自哪里?(离线门控的 logits 蒸馏?人工白名单?自动难负样本?)与类别 logits 如何融合(独立 sigmoid 相乘 / softmax 加背景类)?粗类条件化怎么做才不破坏校准(Y3 教训)?
- **收益**:FDR 0.157→0.12 级,工作点下移 Recall +1-2pp;
- **风险**:分数校准破坏(必须做 2.1 的三项验证)。

## 5.2 细类判别专用头(解耦粗/细监督)

- **证据**:混淆 2,228 次全在兄弟机型;Y3 层次损失失败于耦合 + 校准破坏;FP_CLS/FN_CLS 896 是最大单一错误源;
- **大改设想**:detection 头负责"检不检 + 粗类";**细类判别走独立分支**,只在 top-K 高 IoU 候选上训练细类损失(检测阶段细类可粗,后处理前细类精修);或"coarse logits 共享 + fine logits 残差但分数不合并"——避免 Y3 的两阶段耦合;
- **设计问题**:细类头输入用什么特征(ROI 对齐后的局部特征?全局上下文?);细类损失用什么(CE?度量学习?);与检测分数如何合成最终置信度;
- **收益**:FN_CLS/FP_CLS 896→400 级 → Recall +2pp、FDR -2pp、Macro 全面受益;
- **风险**:两阶段延迟(可在后处理阶段做,时延可控)。

## 5.3 稀有类小样本机制(原型/度量/合成)

- **证据**:HM 17 / LQS 30 个 GT;Y5 靠增强只到 0.647/0.600;Macro 口径下这是最大杠杆;
- **大改设想**:①**细类原型网络**:ship 大类共享 encoder,每细类一个原型向量,判别 = 距离(契合"小样本"赛题叙事);②**模板合成**:MS/QHS crop 变换合成 HM/LQS;③**细类级伪标注半监督**:用高置信 ship 候选 + 几何先验扩充;
- **设计问题**:原型在检测器中如何落地(检测头后?ROI 特征上?);HM/LQS 与 MS/QHS 的差异是否"可合成";
- **收益**:HM→0.85 / LQS→0.75,Macro +0.35 分(25 类口径);
- **风险**:17 个样本过拟合——需要严格 OOF 验证(留出折不可用于任何设计决策)。

## 5.4 小目标恢复(P2 头 / 切片 / 上下文)

- **证据**:91 个三模型全漏 80% 是小目标(≤96px);QHS 36 + FSC 20 占 62%;FSC 中位 37px;
- **大改设想**:①P2(1/4 分辨率)检测头——但时延 +NMS 复杂度;②**类条件切片**:只对 FSC/QHS 相关高密度区域切片放大;③**站点级上下文先验**(source_group 已知机场/港口代理站点,注入"该站点出现某类的先验概率");
- **设计问题**:P2 头与 P3-P5 头如何分配锚点/损失权重;切片选择策略(哪些图切、切几刀)与时延预算的 Pareto;
- **收益**:Recall +0.4-1pp(91 全漏的可及部分),FSC/QHS 是官方专项类;
- **风险**:时延(20s 预算内必须算总账)。

## 5.5 分数校准工程(保校准的系统方法)

- **证据**:Y5 有长尾(P10 0.179,TP<0.7 17.5%);Y3 因校准破坏全盘皆输;Y5@0.05 只差 FDR 0.35pp;
- **大改设想**:①**类内阈值矩阵**:按类 × 尺寸的分数分位数定阈值(数据全有,可离线算出最优);②**校准温度**:对细类/稀有类单独温度缩放;③**背景概率重排**:不用硬阈值,输出"背景分"重排置信度;
- **设计问题**:类内阈值的最优求解(验证集上网格搜索?保序回归?);与 NMS 的交互;
- **收益**:工作点整体右移——Recall 0.92→0.94 且 FDR 不涨;这是**纯后处理、零训练成本**的快速胜利;
- **风险**:验证集过拟合(必须三折内交叉选参)。

## 5.6 教师蒸馏:把 M3(DETR)的异构能力装进 Y5

- **证据**:M3 找回 M1 漏检 1,313(含车辆 56);双漏 320 可补;但 M3 时延 12.40s;
- **大改设想**:用 M3 的 OOF 预测(soft labels + 边界框蒸馏)训练 Y5——单模型拿到异构架构的互补能力,推理 1.89s;
- **设计问题**:框蒸馏怎么对齐(位置/分数/类别软标签);与自蒸馏(Y5 自身)叠加效果;
- **收益**:单模型 Recall 天花板 0.9741→0.99 级,时延不变——**终极形态**;
- **风险**:M3 的噪声(低分假阳)被蒸馏进去;校准影响(必须验证三项)。

## 5.7 层次结构的正确打开方式(Y3 的救赎)

- **证据**:Y3 层次损失失败(校准破坏),但"粗类对、细类错"的瓶颈(3.3)本质是层次问题;
- **大改设想**:层次结构保留,但**粗类 logits 不进最终分数**(只做辅助监督/先验),最终分数只来自细类头;或"粗类先验 + 细类残差"但加分数校准正则(如 Focal 调参/温度);
- **设计问题**:如何让层次先验帮助训练而不污染推理分数;
- **收益**:细类判别增强且保住校准(若成功 = 5.2 的变体);
- **风险**:Y3 已证明这条路容易踩坑,需要更强的验证纪律。
