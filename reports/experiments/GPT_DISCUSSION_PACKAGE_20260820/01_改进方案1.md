## 2. 赛题与硬约束

- 任务：在遥感卫星大图中检测并正确细分类 25 类目标，包括 4 类舰船、20 类飞机、1 类车辆；只有框匹配且细类正确才算 TP。
- 官方匹配 IoU：舰船 0.50、飞机 0.50、车辆 0.35。
- 初赛刚性门槛：整体 Recall ≥ 0.85、整体 FDR ≤ 0.20、单幅 10,000×10,000 图像在单张 RTX 3090 或同等算力设备上 ≤ 20 秒。
- V1.6 排名不是只看总体 pooled 指标，而是比较舰船、飞机、车辆各自的 macro Recall、macro FDR，再加时延，共 7 项排名。大类内每个细类等权，因此 HM、LQS、TU-160 等少样本类不能被头部类掩盖。
- 当前所有关键数字来自 4,481 张训练源图上的正式三折 OOF；它们是迭代开发证据，不是隐藏测试集成绩。10K 全链路时延尚未完成，因此不能声称已经正式过赛。

官方原文见 01～04；项目实验协议见 06。

## 3. 数据、小样本与验证划分

- 全部训练数据：4,481 张源图、20,933 个标注对象、25 个细类。
- 小样本性主要体现在细类支持极不均衡和场景域有限，不是官方定义的固定 K-shot。正式 crop 统计中，HM 17、LQS 30、TU-160 361；FA-18 等头部类超过两千。
- 飞机数据来自 MAR20，但 MAR20 不提供可直接使用的机场 ID。项目通过背景遮挡、DINOv2 局部描述子、VLAD、检索、几何验证和人工校准，构造 60 个机场代理视觉域，用作 CV3 分组约束。
- 正式 CV3 保持来源/机场代理组互斥，并冻结公共数据层、crop manifest 与 OOF 合同；TU-160 的真实视觉域高度集中，fold0 训练侧仅 9 个框，是需要正视的域外少样本压力，而不是简单随机重分就能消除的问题。

## 4. 已完成的正式基础实验

### 4.1 M1：YOLO26-s 检测基线

M1 是正式三折 OOF 检测主干。12 是完整训练、关机恢复、OOF 覆盖和审计报告；13 是选定工作点的机器可读错误分解。

M1 证明了单阶段检测器能够提供较高召回的候选底座，但原始结果存在：

- 飞机细类混淆；
- 大量重复预测与背景 FP；
- 舰船和车辆 FDR 明显偏高；
- 车辆 Recall 明显不足；
- OOF 上开发阈值与隐藏测试泛化之间仍有风险。

### 4.2 P03/P04：对象 crop 上限与教师表征

14 是正式 CV3 复验，不要用早期探索结果替代它：

- P03 ConvNeXt-T 全量微调、GT crop 条件下 pooled OOF macro Recall = 0.9287；飞机 20 类 macro Recall = 0.9524；舰船 4 类 macro Recall = 0.7950。
- P04 frozen feature probe：DINOv2-B 0.8294 > ConvNeXt 0.7815 > CleanDIFT 0.7036。
- 结论不是“DINOv2 一定胜过微调 ConvNeXt”，而是：DINOv2-B 是三种冻结教师里最强；CleanDIFT 没有进入下一阶段的证据；GT crop 上限很高，但真实 proposal 域仍需单独训练和验证。

## 6. 当前错误预算与真正瓶颈

R1-6 的分层错误计数：

| 错误 | 数量 | 含义 |
|---|---:|---|
| FP_BG | 1,539 | 无法归因到 GT 的背景/伪目标预测 |
| FP_CLS / FN_CLS | 777 / 777 | 框能覆盖目标但细类错误 |
| FN_MISS | 624 | 没有足够匹配候选的真实漏检 |
| FP_DUP | 104 | 剩余重复预测 |
| FP_LOC / FN_LOC | 62 / 62 | 同细类但定位未过 IoU 门槛 |

按大类看：

- 舰船：FP_BG 723、FN_MISS 274、FP_CLS 110；宏观指标最差，简单 NMS 会误删 TP。
- 飞机：FP_CLS 667、FP_BG 584、FN_MISS 196；当前分类和重复框已得到明显改善，但细类混淆仍是最大剩余结构性错误。
- 车辆：FP_BG 232、FN_MISS 154；只有一个细类，核心是目标性、尺度和候选召回，不是细分类。

因此下一步不能再把主要资源放在“飞机分类器上无条件继续叠头”，也不能用统一后处理同时处理三大类。

## 7. 已验证的正向与负向证据

### 保留的正向证据

- Y1-C2：fold-train 先验校准改善飞机细类分布，进入主线（20）。
- proposal 域 CE 微调 + D4：优于直接使用 GT crop P03 教师，也优于更复杂的选择性 KD（22、23）。
- 飞机同细类 NMS@0.50：不损 Recall，大幅降低重复 FP（29、34、35）。
- view-consistency：获得高召回 Pareto 备选，但 FDR 稍差，不替代 R1-6（26、28）。

### 已停止或暂不进入主线

- Y2 位置敏感上采样：40 epoch 配对快筛无收益（21）。
- 类中心损失：净损失 TP，macro Recall 下降（24）。
- 由类别名推导的结构属性头：几乎无独立收益（25）。
- 自适应 D4：不如固定 D4（27）。
- CE 与 view-consistency 等权概率集成：FP 增加、macro Recall 下降（28）。
- 将 NMS 直接扩展到舰船/车辆：减少 FP 但误删 58 TP，停止（30）。
- 按来源分位数和尺寸做固定预算重排：来源项与原分数等价；加入尺寸后 Recall 降、FDR 升（31）。
- CleanDIFT frozen feature：正式 CV3 明显落后 DINOv2-B，不建议仅因“扩散创新”强行进入模型（14）。

这些负向实验是路线边界，不应在未提出新机制和新证据前重复搜索同类超参数。

## 11. 重要解释边界

- “正式 CV3”表示使用冻结的来源/机场代理互斥三折和 OOF 合同，不等于官方隐藏测试。
- “scientific admission=true”表示在当前证据上方向成立；“formal admission=false”通常表示仍缺独立确认或部署闭环。
- P03/P04 是对象 crop/冻结表征实验，不是端到端检测成绩。
- FP_BG 是按当前层级归因规则得到的诊断标签，不等于全部都是肉眼显然的纯背景；N0 盲审正是为了拆分 hard negative、疑似漏标、截断目标等子型。
- 15 的 leaderboard 同时包含探索性、正式、失败和候选行，必须结合 `status`、`evaluation_scope` 与 `notes` 阅读，不能仅按单个数值排序。
- 当前主线目标不是证明某个论文模块“新”，而是以错误预算为依据，形成可消融、可回退、可在 10K 时延约束下部署的系统创新。

# 一、一页式优先级结论

|顺序|路线|当前决策|直接解决的错误|
|---|---|---|---|
|**下一步**|**N0 → N2-CFG 粗类条件式前景验证**|**唯一主实验**|舰船、车辆 `FP_BG`|
|**下第一步**|**N2-P：低分 reserve proposal 晋升**|N2-CFG 正式通过后启动|舰船、车辆已有低分候选未被选中造成的 `FN_MISS`|
|**下第二步**|**M3-R：仅补充 M1 真正无候选区域**|完成 paired OOF 后条件接入|reserve pool 之外的剩余 `FN_MISS`|
|并行硬门禁|E：全局对象聚合、canonical crop、10K 时延|必须继续，但不作为主实验|跨 tile 重复、截断视图、一次一对象推理、20 秒合同|
|暂时冻结|飞机继续叠分类头、属性头、类中心、概率融合|不再投入主资源|已有负向或收益边际不足|
|停止|全局 M1+M3、舰船/车辆直接 NMS、再跑 P2 网格、扩散特征|不再重复|已被负向证据封住|

选择 N2-CFG 的原因不是“背景 FP 数量最多”这一句泛泛判断，而是它同时满足四个条件。

第一，R1-6 剩余 2,482 个 FP 中有 1,539 个属于 `FP_BG`，占 **62.0%**。更关键的是，舰船的 958 个 FP 中有 723 个 `FP_BG`，占 **75.5%**；车辆的 267 个 FP 中有 232 个 `FP_BG`，占 **86.9%**。这两类又恰好是官方七项排名中最薄弱的四项：舰船 Recall/FDR 和车辆 Recall/FDR。〔34、35〕

第二，它是后续召回恢复的前置能力。当前车辆已经有 FDR 0.527，再直接加入更多候选，很容易让 Recall 和 FDR 一增一坏。只有先证明系统能够识别“这个候选到底是不是该粗类的真实对象”，才有资格向低分候选池或 M3 候选池扩张。

第三，它不碰 R1-6 已经稳定的飞机细分类、不改框、不改类，仅执行删除，因此具备最干净的变量隔离和最安全的回退路径。

第四，它的计算量远小于再运行一个检测器。现有 ConvNeXt-T 单视图在 RTX 3090 上约为 1,270–1,350 crops/s，峰值显存约 1.05 GiB；把它放在全局对象聚合之后，每个对象只调用一次，具备明确的 20 秒落地空间。〔22、23、37〕

作为计数上的直观说明，在 **完全不损失 TP** 的理想条件下，若只删除 20% 的对应 `FP_BG`：

|指标|当前|20% `FP_BG` 删除后的计数示意|
|---|--:|--:|
|Overall pooled FDR|0.1131|约 0.1004|
|舰船 pooled FDR|0.2987|约 0.2656|
|车辆 FDR|0.5266|约 0.4789|

这只是根据当前错误计数计算的潜在迁移，不是预期实验成绩；它说明该方向即使只取得中等强度的拒识能力，也足以显著改变舰船和车辆的排名位置。

# 二、问题 A：下一步主实验的完整定义

## 2.1 实验名称与核心假设

建议冻结为：

> **N2-CFG：Audited Coarse-conditioned Foreground Gate**

核心假设是：

> 对 R1-6 保留下来的舰船和车辆候选，原始图像中的对象证据能够提供与检测器置信度互补的前景判断；在不改变类别和框的情况下，可以安全删除一部分真实背景误报。

这里最重要的边界有三条：

1. **只做 `background_reject`，不做 reclassify，不做 joint。**
    
2. **舰船、车辆进入正式门控；飞机只做 shadow evaluation，首轮不改变飞机输出。**
    
3. **只允许人工确认的 `clear_background` 作为负样本。**
    

这严格继承了 N2 v2 已修复的合同，也避免重演 N2 v1 把所有 `FP_BG` 自动当背景、混淆 oracle/deployable 标签、用 held-out fold 选 checkpoint 等问题。〔32、33〕

---

## 2.2 门控位置

当前普通图 OOF 中：

```text
M1
→ Y1-C2
→ 飞机 proposal-domain CE
→ D4
→ 飞机同细类 NMS@0.50
→ N2-CFG（仅舰船/车辆生效）
→ 最终输出
```

最终 10K 部署中应调整为：

```text
tile 检测
→ 恢复全局坐标
→ 类别无关 global object 聚合
→ 选择 canonical box / canonical crop
→ 每个 global object 只运行一次 N2-CFG
→ 保留或删除
```

也就是说，**科学验证阶段放在 R1-6 之后，部署阶段放在 E 的全局对象唯一化之后**。这样可以避免同一个跨 tile 对象被重复裁剪和重复判断，同时利用完整的 canonical 视图减少 tile-edge 截断造成的假背景判断。〔37〕

---

## 2.3 输入

N2-CFG 每个候选只使用：

- 原图上按 canonical bbox 扩展 `1.25×` 后的 `224×224` 单视图 crop；
    
- R1-6 当前候选分数；
    
- 当前预测粗类：ship / aircraft / vehicle。
    

不使用：

- source ID；
    
- 固定尺寸分位数；
    
- 图像位置分位数；
    
- 25 个类别阈值；
    
- D4 推理；
    
- CleanDIFT 或扩散特征；
    
- M3 分数。
    

选择 `context_1p25` 而不是继续使用纯 tight crop，是因为这里解决的是“对象还是背景”，需要看到港口结构、道路纹理和目标周围关系；飞机细分类仍继续使用原来的 tight crop 和 D4，不受影响。输入尺度应直接冻结，不再比较 1.15、1.25、1.5 等网格。

---

## 2.4 样本构造

### 正样本

使用 N2 v2 合同中的：

- `deployable_positive`；
    
- `oracle_positive`。
    

对于前景判断而言，两者都是真实对象。采样时采用两级均衡：

1. 舰船、飞机、车辆粗类等概率；
    
2. 粗类内部按细类近似等概率，而不是按实例数自然采样。
    

这样 HM、LQS、TU-160 等少样本类不会被 FA-18、MS 等头部类掩盖，训练目标与官方 macro 排名一致。

### 负样本

只有人工盲审为：

```text
clear_background
```

的候选进入负样本池。

以下标签全部进入 ignore，不作为背景，也不强行作为前景：

```text
plausible_unlabeled_or_ambiguous_target
poor_localization_of_known_target
duplicate_or_fragment_not_captured
invalid_crop_or_render
```

其中 `invalid_crop_or_render` 还必须触发数据资产修复，而不是进入任何训练。

### 采样

每个 batch 固定：

- 50% foreground；
    
- 50% audited clear background；
    
- 粗类均衡；
    
- 正样本在粗类内部细类均衡；
    
- 负样本按 fold、score bin、source group 分层；
    
- 同一个 `proposal_uid` 不得因重复审核卡多次进入训练。
    

不需要人工设计困难度损失。先让困难样本通过采样进入训练，而不是再引入 focal loss、中心损失或额外属性头。

---

## 2.5 模型

推荐保持 ConvNeXt-T，不引入新 backbone：

```text
context_1p25 crop
→ ConvNeXt-T shared trunk
→ shared foreground logit
→ coarse-specific residual head
→ p_foreground
```

可以写为：

[  
z_i=z_{\mathrm{shared}}(h_i)+z_{c_i}(h_i),\qquad  
p_i^{fg}=\sigma(z_i),  
]

其中 (c_i) 是候选当前粗类。

实现上保留三个粗类 head，但正式首轮只启用 ship 和 vehicle；aircraft head 只记录 shadow 结果。这样既能验证粗类条件化是否必要，也能保证飞机指标在代码结构上严格不变。

训练策略固定为：

- 快筛：冻结 backbone，只训练共享线性头与粗类 residual head；
    
- 正式模型：冻结 ConvNeXt 前三个 stage，只训练最后一个 stage 和 heads；
    
- 固定 5 epoch；
    
- 固定 final-epoch checkpoint；
    
- 不 early stopping；
    
- 不根据 held-out fold 选择 checkpoint；
    
- 单一固定 seed。
    

### 初始化边界

现有 P03-F checkpoint 可以用于 Level-E 快筛。

正式 outer-fold-pure 实验中，不能直接使用一个见过 `inner_score_calib` 图像的 P03-F 初始化。更严格的做法是：

```text
inner_model_train
→ 训练 P03-inner crop checkpoint
→ 初始化该 outer fold 的 N2-CFG
```

或者退回公共 ImageNet ConvNeXt-T 初始化。推荐第一种，因为它保留了 P03 已证明有效的对象表示，同时不破坏 inner calibration 的独立性。

---

## 2.6 损失

不需要复杂多任务损失。建议使用粗类宏均衡的 BCE：

# [  
\mathcal L_{\mathrm{CFG}}

\frac{1}{|\mathcal C|}  
\sum_{c\in\mathcal C}  
\left[  
\mathbb E_{x\sim P_c}\mathrm{BCE}(1,p_c(x))  
+  
\mathbb E_{x\sim N_c}\mathrm{BCE}(0,p_c(x))  
\right].  
]

第一轮不增加：

- 类中心；
    
- 属性辅助；
    
- KD；
    
- consistency；
    
- quality head；
    
- box loss。
    

这些要么已经有负向证据，要么会让“前景判断是否成立”失去可解释性。〔24、25、26、28〕

---

## 2.7 分数融合与删除规则

不能直接拿 `p_foreground` 再扫一个阈值。建议使用一个低容量、单调的风险校准器：

[  
q_i=  
\sigma\left[  
\alpha,\operatorname{logit}(s_i^{R1})  
+  
\beta,\operatorname{logit}(p_i^{fg})  
+  
\gamma_{c_i}  
\right],  
\qquad \alpha,\beta\ge 0.  
]

只有五个左右的有效参数：

- 两个全局斜率；
    
- 三个粗类偏置。
    

不加入 source、size、位置等变量，避免重新走到材料 31 已经失败的固定来源/尺寸重排路线。

最终只使用**一个全局删除阈值**：

```text
q < τ_drop → 删除
q ≥ τ_drop → 保留
```

粗类差异由 head 和粗类偏置表达，不允许再产生 25 个细类阈值。

阈值只在 `inner_score_calib` 上确定，目标是：

> 在预先冻结的 Recall 安全约束下，最大化可删除 FP 数量。

外层 held-out fold 不得参与阈值选择。

---

# 三、配对快筛、正式三折与停止条件

## 3.1 先修正 N0 资产口径

这里有一个需要项目组立即改正的材料不一致：

- 材料 18 是规划口径：首轮至少 600 个真实候选，原始一致率 ≥0.90，Cohen’s κ≥0.75；
    
- 材料 32 的当前 v3 权威包实际为：268 个唯一候选、54 个重复卡，共 322 张；编译脚本只要求一致率 ≥0.85。
    

因此应该区分：

- **0.85：技术编译最低门槛；**
    
- **0.90 + κ≥0.75：科学放行门槛。**
    

当前 322 张足以做误差构成审计和 Level-E 方向快筛，但不能直接被描述成“已经具备正式 N2 训练数据”。〔18、32〕

---

## 3.2 Level-E 配对快筛

使用当前 R1-6 OOF 和 N0 v3 标签，做 leave-one-fold-out 的快速验证：

|编号|模型|目的|
|---|---|---|
|S0|仅 R1-6 score 的单调校准器|排除收益只是重新调阈值|
|S1|shared foreground head + score|判断图像前景证据是否存在|
|S2|coarse-conditioned head + score|判断粗类条件化是否必要，主候选|

这三项属于一个主实验内部的最小消融，不是三条新路线。

沿用材料 18 的快筛门禁：

- pooled `FP_BG` 至少减少 10%，即至少约 154 个；
    
- Overall Recall 下降不超过 0.2 个百分点；
    
- 任一粗类 Recall 下降不超过 0.5 个百分点；
    
- 至少 2/3 fold 同向；
    
- S2 必须在相同 Recall 约束下明显优于 S0，否则说明图像模型没有提供独立证据。
    

当前主门控只启用舰船和车辆，因此飞机 TP、FP、FN 必须逐条完全一致。

---

## 3.3 正式 outer-fold-pure 三折

快筛通过后，正式实验不能直接复用当前两个 OOF fold 的候选训练第三折，因为训练候选的上游检测器可能见过第三折图像。这一点材料 18 已经正确指出。

对每个 outer fold (f)，只在 outer-train source groups 内，以 seed `202625` 固定划分：

```text
inner_model_train   ≈ 70%
inner_error_mining  ≈ 15%
inner_score_calib   ≈ 15%
```

具体流程：

1. `inner_model_train` 训练一个 `M1-INNERCAL/f`；
    
2. 用该模型预测 `inner_error_mining` 和 `inner_score_calib`；
    
3. 从 `inner_error_mining` 构造独立盲审包；
    
4. 只用其中 `clear_background` 训练 N2-CFG；
    
5. `inner_score_calib` 只拟合低容量校准器与单一阈值；
    
6. 完全冻结后应用到 outer-val 的 R1-6 输出；
    
7. outer-val 只评一次，不选模型、不改阈值。
    

正式成本就是材料 18 已冻结的 **3 个额外 YOLO26-s/1024/160-epoch 辅助 run**，再加三个很轻的 crop 模型训练。〔18〕

---

## 3.4 建议的正式准入门禁

快筛门禁可以保留原计划的 10%，正式准入应针对 R1-6 的新水平进一步收紧：

|维度|正式门禁|
|---|---|
|`FP_BG`|pooled 至少减少 10%，即 ≥154；其中舰船至少减少 15%，车辆至少减少 10%|
|总 FP|至少净减少 150|
|飞机|结构旁路，TP/FP/FN 完全一致|
|车辆 Recall|**不得损失任何 TP**|
|HM、LQS|各自不得损失任何 TP|
|舰船|总 TP 损失最多 4 个，且不得集中在单一少样本类|
|Overall Recall|下降不超过约 0.02 个百分点|
|舰船 macro FDR|至少改善 2 个百分点|
|车辆 FDR|至少改善 2 个百分点|
|折稳定性|≥2/3 fold 同向；任何 fold 的舰船/车辆 FDR 不得恶化超过 0.5 个百分点|
|来源稳健性|单一 source group 不得贡献超过 40% 的净 FP 删除|
|统计|source-group paired bootstrap 95% CI；HM/LQS/TU-160 同时报原始计数与精确区间|
|对象吞吐|RTX 3090 单视图 ≥1,000 crops/s，峰值显存 ≤1.5 GiB|
|全链路|10K p95 ≤18 秒作为内部安全线，官方硬线仍为 20 秒|

这里对车辆要求零 TP 损失并不苛刻：车辆只有 402 个 GT，损失一个 TP 就是约 0.249 个百分点 Recall。一个为了改善车辆 FDR 而损失车辆 Recall 的 rejector，很容易在官方两项排名中相互抵消。

---

## 3.5 停止条件

出现任一情况即停止，不再继续搜网络、loss 或阈值：

1. S1/S2 在相同 Recall 约束下不优于 score-only S0；
    
2. `clear_background` 在舰船或车辆中覆盖不足，且补充审计后仍不足；
    
3. 正式结果主要由一个 source group 驱动；
    
4. outer-fold-pure 结果不足 2/3 fold 同向；
    
5. 车辆丢失 TP；
    
6. HM/LQS 丢失 TP；
    
7. 需要 source-specific 或 fine-class-specific 阈值才能成立；
    
8. FP 下降主要来自飞机，而舰船、车辆排名没有实质改善；
    
9. 对象阶段使 10K p95 超过 18 秒。

# 四、问题 B：下一步完成后的“下两步”决策树

```text
N0 审核回收
│
├─ A. 审核科学门禁未通过
│    ├─ 一致性不足 → 修订说明并复审，不训练 N2
│    ├─ clear_background 太少 → 只扩充缺失粗类/score strata
│    └─ 截断/碎片占主导 → E canonical crop 优先于背景拒识
│
└─ B. 审核通过
     │
     └─ N2-CFG Level-E 快筛
          │
          ├─ B1. 无独立图像信号，和 score-only 等价
          │     ├─ 停止 N2
          │     ├─ 保留 R1-6
          │     └─ 转入 M3 paired OOF，分析真正互补 FN_MISS
          │
          ├─ B2. FP_BG 明显下降，但损失 Recall
          │     └─ 只允许一次固定救援：
          │          冻结模型，改为“视觉低分 AND R1低分”双证据删除
          │          ├─ 通过 → 进入正式 outer-pure
          │          └─ 仍失败 → 停止 N2，模型只作诊断风险特征
          │
          └─ B3. 快筛通过
                └─ 正式 outer-fold-pure replay
                     │
                     ├─ 正式失败/折间不稳
                     │     ├─ 不做来源阈值
                     │     ├─ R1-6 完整回退
                     │     └─ M3 paired + E 全链路
                     │
                     └─ 正式通过
                           ├─ 下第一步：N2-P reserve proposal 晋升
                           └─ 下第二步：M3-R 只补 residual no-candidate GT
```

---

## 4.1 成功分支的下第一步：N2-P 低分候选晋升

一旦 N2-CFG 证明自己能够在不损 Recall 的前提下判断真实对象，下一步不应马上训练新检测器，而应先利用 M1 已经存在的低阈值候选。

冻结候选地板显示：

- 舰船当前 R1-6 Recall 约 0.8386，低阈值候选 floor 约 0.8993，对应大约还有 **163 个 GT** 存在可匹配候选但未成为当前 TP；
    
- 车辆当前 Recall 约 0.5970，候选 floor 约 0.7985，对应大约还有 **81 个 GT** 已经存在于 M1 低分候选池中。〔13、18、21、35〕
    

这些数字是候选上限，不代表一定能够恢复，但它们说明：

> 在重新训练 P2 或引入 M3 之前，先把已有候选用好，是成本最低、证据最直接的召回路线。

N2-P 使用同一个模型形成三段式决策：

```text
q < τ_drop
    → 删除当前候选

τ_drop ≤ q < τ_promote
    → 只保留原本已进入 R1-6 的候选

q ≥ τ_promote
    → 允许从 score≥0.001 的 reserve pool 晋升
```

其中 `τ_promote` 必须明显高于 `τ_drop`，防止低分候选大量涌入。

准入门禁建议：

- 车辆净增加至少 21 个 unique TP；
    
- 增量来自 ≥3 个 source groups；
    
- ≥2/3 folds 同向；
    
- 车辆 FDR不得恶化；
    
- 舰船净增加至少 20 个 TP，且 ship macro FDR 不恶化；
    
- 新增候选不得主要变成 `FP_BG`；
    
- 不增加新的 detector 推理。
    

这一步是对 Y2/P2 负向结论的正确回应：Y2 说明无差别增加 P2 候选没有发现新的车辆目标，不代表现有低分候选没有价值。N2-P 用的是内容驱动目标性判断，与 P2 的“增加特征层后候选更多”是不同机制。〔21〕

---

## 4.2 成功分支的下第二步：M3-R 残余候选恢复

N2-P 完成以后，将 GT 分成：

1. R1-6 已正确覆盖；
    
2. M1 reserve pool 可覆盖但此前未选中；
    
3. M1 在 `score≥0.001` 下仍无可匹配候选。
    

M3 只对第三类承担责任。

M3 的分析顺序固定为：

```text
M1-only TP
M3-only TP
共同 TP
M1-only FP
M3-only FP
oracle union
按粗类、fold、source group、尺寸和边界分层
```

只有满足材料 18 中已经合理的门禁才进入推理：

- ≥2/3 fold；
    
- ≥3 source groups；
    
- 新增至少 21 个 unique vehicle GT，或总计净增至少 30 TP；
    
- 经 N2-CFG 后 Overall FDR ≤0.17；
    
- 10K p95 ≤18 秒。
    

不满足时，M3 只能作为：

- hard-positive 发现器；
    
- 训练期教师；
    
- near-miss 诊断工具；
    

不能成为永久全图双模型。〔18、36〕

---

## 4.3 “FP 降了但 Recall 也掉了”应怎样改

只允许一次低自由度救援，不重新训练模型：

> 将硬删除改成“双证据一致才删除”的 abstention gate。

即：

```text
N2-CFG 明确判断为背景
AND
R1-6 原始分数也处于 inner-calib 的安全低分区
→ 删除

两者不一致
→ 保留
```

进入 E 以后还可再加一个安全规则：

```text
存在第二个 tile/view 对同一 global object 提供支持
→ 即使局部 crop 判断较弱，也先保留
```

这是一种“保守拒识”，不是继续扫阈值。模型、crop、训练数据全部冻结，只改变预注册的低容量决策逻辑。

若该救援仍不能满足车辆零 TP 损失和 HM/LQS 零 TP 损失，N2 应停止进入输出链，只能作为 E 的困难对象诊断特征。

---

# 五、问题 C：怎样避免继续对同一 OOF 过拟合

必须先承认一个事实：

> 当前 CV3 OOF 已经被多次用于路线选择。即使重新做 bootstrap 或换一个统计检验，也无法把已经发生的“多次看结果再决策”变回真正独立验证。

能做的是从现在开始，把训练泄漏、阈值泄漏和继续试错严格切断。

## 5.1 三层协议

|层级|允许做什么|能声称什么|
|---|---|---|
|Level-E 快筛|当前 OOF cross-fit、现有 N0 标签、低容量模型|方向是否值得继续|
|Level-F outer-pure|70/15/15 inner split、辅助 M1、独立 hard negative、独立 calibration|内部严格科学证据|

# 六、问题 D：三大类必须拆成不同决策路径

答案是明确的：**必须拆。**

统一检测器可以共享，统一后处理不应继续保留。

|大类|当前主要错误|推荐决策路径|禁止继续做什么|
|---|---|---|---|
|舰船|`FP_BG=723`、`FN_MISS=274`，macro Recall/FDR 均差|N2-CFG 拒识 → reserve pool 晋升 → M3 残余恢复 → global context|直接 NMS、统一阈值、只看 pooled|
|飞机|`FP_CLS=667`、`FP_BG=584`、`FN_MISS=196`|保留 R1-6；N2 首轮旁路；必要时做 D4 蒸馏压缩|类中心、属性头、等权融合、继续叠普通分类头|
|车辆|`FP_BG=232`、`FN_MISS=154`，只有一个细类|N2-CFG 目标性 → 低分 reserve pool 晋升 → M3/专用 proposal|细分类模型、直接 NMS、再次无条件 P2|

## 6.1 舰船

舰船是最适合 N2-CFG 的类别。

它的 958 个 FP 中有 723 个 `FP_BG`。当前问题不是“舰船分类不够复杂”，而是港口、海岸线、建筑、条带纹理和局部结构被当成舰船对象。

同时 HM、LQS 极少样本，macro 排名对单个 TP 极其敏感，因此：

- 使用 context crop；
    
- 按舰船细类均衡正样本；
    
- HM、LQS 零 TP 损失；
    
- 不允许为舰船单独调四个阈值；
    
- global canonical crop 后再判断；
    
- 不再尝试直接舰船 NMS。
    

在 N2 通过后，舰船再进入低分 reserve pool 晋升。其候选 floor 约 0.8993，说明现有 M1 候选中仍有一部分召回空间，不需要第一时间训练新检测器。

---

## 6.2 飞机

飞机已经形成一条足够强的独立主线：

```text
C2
→ proposal-domain CE
→ D4
→ 同细类 NMS@0.50
```

其 macro Recall 0.9406、macro FDR 0.0729，当前再增加普通分类头的收益优先级很低。〔23、29、34〕

剩余 667 个分类错误主要应被看作：

- TU-160 等极端域外少样本；
    
- 特定混淆对；
    
- 视角与来源域问题。
    

但类中心、结构属性头、CE/consistency 等权融合已经给出负向或不充分证据。因此飞机下一阶段只做两件事：

1. N2 aircraft head 作为 shadow，确认背景判断是否有无损收益，但不进入主输出；
    
2. E 证明 D4 成本过高时，做 **D4 ensemble distribution → single-view student** 蒸馏。
    

后者解决的是视角不变性和时延，而不是 `FP_BG` 或定位。

---

## 6.3 车辆

车辆最紧急，因为 Recall 和 FDR 两项同时很差；但顺序不能变成“先增加更多框”。

车辆只有一个细类，因此不需要任何细分类器。它真正需要的是：

1. 对象性判断；
    
2. 低分候选恢复；
    
3. 新候选形成。
    

目前 402 个车辆 GT 中：

- R1-6 只得到 240 TP；
    
- 低阈值候选 floor 约能覆盖 321 个；
    
- 说明约 81 个当前漏检目标已经存在于 M1 reserve pool；
    
- 仍约有 81 个目标在现有 M1 候选中真正不可恢复。
    

因此车辆的合理顺序是：

```text
N2-CFG：先让现有输出更干净
→ N2-P：从已有 reserve pool 恢复最多约 81 个目标中的一部分
→ M3 / 新 proposal：只处理 reserve floor 之外的目标
```

Y2/P2 的负向结果已经说明“把 P2 候选数量提高 36%”并没有增加车辆候选 floor，不能再原样重复。后续车辆 proposal 必须是新的互补机制，例如 M3 独有候选或风险区域条件检测，而不是再换一个 P2 配置。〔21〕

# 九、问题 E：创新性与工程可落地性怎样同时成立

最终方案最适合的创新叙事不是“YOLO 加了多个新模块”，而是：

> **面向大尺度遥感检测的、错误预算驱动的粗类条件式对象证据路由。**

完整逻辑可以写成：

1. 单阶段检测器负责高召回候选；
    
2. 全局对象层负责跨 tile 唯一化与 canonical view；
    
3. 粗类条件式前景证据负责安全拒绝背景；
    
4. 同一前景证据以更严格门槛晋升低分 reserve proposal；
    
5. 异构检测器只负责前两者都无法覆盖的残余目标；
    
6. 所有学习型门控通过 group-pure nested calibration 控制 Recall 风险。
    

这个叙事具备以下优点：

- 每个模块对应一种已量化错误；
    
- 每个模块都有独立消融；
    
- 每个模块都能 feature-flag 回退；
    
- 不需要全图永久运行两个大型检测器；
    
- 不依赖 25 个类别阈值；
    
- 与 V1.6 的粗类分路、细类 macro 排名直接对应；
    
- 部署路径与科学故事是一条链，而不是论文模块和工程代码两套系统。
    

---

## 9.1 DINOv2 应放在哪里

DINOv2-B 在正式 frozen probe 中优于 ConvNeXt frozen feature 和 CleanDIFT，因此它具备教师候选资格，但现在不应直接进入推理。〔14〕

只有两种合理用途：

1. **N2-CFG false-rejection teacher**：当 ConvNeXt 在相同 FP 删除率下误删真实对象时，用 DINO foreground margin 蒸馏到轻量学生；
    
2. **D4 ensemble-to-single-view teacher**：压缩飞机八视图推理。
    

准入仍应要求：

- 相同 Recall 下进一步删除背景，或相同 FP 删除下减少 TP 误删；
    
- ≥2/3 fold；
    
- 净改正至少 10 个对象；
    
- 正式推理不运行 DINO。
    

---

## 9.2 为什么 CleanDIFT 负向结果不矛盾

CleanDIFT 的正式负向结果说明：

> 扩散冻结特征作为对象 crop 表示，在当前任务上不如 DINOv2-B，也没有证据支持其进入主线。

这不妨碍 DINO 蒸馏，因为：

- 二者不是同一表征；
    
- DINO 已有正式 probe 正向证据；
    
- DINO 在这里解决的是对象不变性或模型压缩；
    
- 并不是借助扩散特征修定位框；
    
- 当前 `FP_LOC` 只有 62，对 bbox diffusion 的直接错误容量也很小。
    

因此近期不建议恢复：

- CleanDIFT 大规模实验；
    
- SD1.5 背景融合；
    
- bbox diffusion；
    
- 生成式框修正。
    

除非 N0 审核明确发现某一种可复现的背景子型占据主要错误，并且真实样本不足，否则生成增强没有进入队列的依据。〔12、14、18〕

## 9.3 20 秒工程合同

最终部署应把预算分成：

# 最终路线定案

可以把未来三个科学步骤正式冻结为：

```text
Step 1：N2-CFG
N0 审核驱动的舰船/车辆粗类条件式前景拒识
目标：FP_BG↓，Recall 基本不动

Step 2：N2-P
用同一个前景证据从 M1 低分 reserve pool 晋升舰船/车辆候选
目标：FN_MISS↓，不增加 detector

Step 3：M3-R
只为 M1 reserve floor 之外的真实无候选目标提供异构补充
目标：残余 FN_MISS↓，条件计算，不做全图永久双模型
```

其中 E 全局对象层贯穿三步，并作为最终 10K/20 秒释放门禁。

这条路线的核心价值在于，它不是继续给模型“增加能力”，而是把当前已经存在的三种能力——高召回检测、对象 crop 判断和异构候选发现——按错误类型与风险边界组织成一个可验证、可回退、可部署的系统。R1-6 保持不动，任何新阶段失败都不会破坏当前最好结果；任何新阶段成功，都能明确说明究竟迁移了哪一类 FP 或 FN。
