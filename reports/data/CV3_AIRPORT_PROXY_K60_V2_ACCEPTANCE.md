# K60 机场代理组正式 CV3 v2 验收报告

## 1. 最终结论

`cv3_airport_proxy_k60_v2` 已通过输入、分组、类别覆盖、训练下限、
TU-160 压力折、确定性和全仓回归检查，可作为后续 P03/P04 正式复验、
OOF 生成及 P06 后续实验的统一三折划分。

错误的 `cv3_airport_proxy_k60_v1.json` 已从工作树删除，不再作为可选
实验入口。其错误原因和历史结论保留在本报告及 Git 历史中；正式实验只
允许读取 v2。

## 2. 修正内容

1. MAR20 K60 映射成为强制且不可变的输入：
   - 恰好 3,073 张 MAR20 图；
   - 恰好 60 个 `mar20-airport-proxy-001..060`；
   - 输出 `group_id` 逐图等于 K60 CSV；
   - 缺行、多行、重复图、空组号或非法组号立即失败。
2. 旧 `near_duplicates_mar20.json` 仅做审计，不再参与并查集合并。
   其中 7 个候选组有 4 个跨 K60，但它们不会改写任何 K60 组。
3. 采用经过审查并冻结的 255 个来源组到三折映射：
   - 每个来源组只属于一个 fold；
   - 每张图恰好作为一次验证样本；
   - 25 个细类在每个 fold 均至少有一个验证来源组；
   - 默认每个训练折至少保留 30 个框；
   - 数据量不可能满足通用 30 框的 HM、LQS、TU-160 分别冻结为
     11、20、9 框下限。
4. 所有科学门禁在写正式 JSON 之前完成；失败返回非零状态且不落盘。
5. 输入 SHA、标签集合指纹、来源组统计指纹、冻结映射 SHA 和算法协议均
   写入 manifest。

## 6. TU-160 的解释

TU-160 只来自三个不可拆 K60 组：

- `018`：352 框 → fold 0；
- `020`：8 框 → fold 1；
- `019`：1 框 → fold 2。

因此三个训练折必然分别只剩 9、353、360 个 TU-160 框。9-shot 折是严格
来源隔离后的数学必然结果，应作为压力折单独报告；不得拆 K60 组来改善
数字，也不得把该折删除。

## 7. 结构性警告

下列现象来自不可拆来源组，并非代码失败：

- TU-160 最大组占 97.5%；
- E-3 某折占 70.9%；
- B-52 某折占 64.8%；
- TU-95 的一个验证折只有一个来源组。

正式结论应报告三折结果、均值和标准差，并保留逐折结果，不能只选择对
模型最有利的 fold。TU-160 压力折建议同时给出该类单独指标。

```bash
  --data-root ../data \
  --airport-groups data/groups/mar20_airport_proxy_k60_for_b.csv \
  --assignment data/splits/cv3_airport_proxy_k60_v2_groups.json \
  --near-duplicates reports/data/near_duplicates_mar20.json \
  --output data/splits/cv3_airport_proxy_k60_v2.json \
  --audit-output reports/data/cv3_airport_proxy_k60_v2_audit.json
```
