# A 主线 1：车辆候选恢复 —— near-miss 审计协议

更新日期：2026-08-10
依据：`doc/20260804.md`（A = 主线 1 主责）+ 总纲 §5.1/§4.3 + N0 证据

## 1. 问题与假设

**问题**：车辆 402 个 GT 中，工作点（score≥0.051）只检出 251 个（Recall 0.6245），
漏检 151 个。其中：
- **71 个**有车辆候选（IoU≥0.35）但 score<0.051 —— 后处理/阈值可救；
- **80 个**完全无候选（连低分车辆候选都没有）—— 候选形成失败。

**假设（可证伪）**：
> 80 个无候选目标主要因高步长特征（P3/P4）对 43×44px 目标响应不足，
> 而非 NMS/max_det 截断或 tile 边界切掉。若成立，加入高分辨率候选通路
> 应新增唯一车辆 GT，且新增 FP 不主要来自背景纹理。

## 2. 数据摸底（已完成 2026-08-10）

| 类别 | 数量 | 特征 |
|---|---|---|
| 工作点匹配 | 251 | Recall 0.6245 |
| 低分候选被滤 | 71 | 有候选但 score<0.051；17 个来源组，最集中 site_N25.20-E121.42（20） |
| 完全无候选 | 80 | IoU≈0；13 个来源组，site_N35.89-E126.62（18）+ site_N25.20-E121.42（14）占 40% |

无候选 80 个目标特征：
- 尺寸：短边中位约 32px（范围 12-48），宽×高均值 38.8×48.3
- edge_risk：76/80 非边界（4 个贴边）→ **绝大多数不是 tile 边界切掉**
- fold 分布：0:23 / 1:33 / 2:24（跨折均匀，非单折问题）
- 来源组：13 组，其中 2 组占 40%（来源集中是根因之一）

## 3. 审计步骤（Level E，快速探索）

### 3.1 后处理审计（本机 CPU 可做，无需推理）
- 71 个低分候选：检查它们在 NMS 前/后的分数、是否被 max_det 截断；
- 低分候选被压的原因（NMS 相邻高框 / 分数本身低 / 类别竞争）。

### 3.2 特征响应审计（服务器 GPU，需 checkpoint hook）
对 80 个无候选目标所在图，用对应 fold 的 M1 checkpoint 做 hooked 推理：
- P2/P3/P4 特征图在目标中心位置的响应值；
- 目标中心是否落在 anchor 匹配区域；
- 各尺度层的 assignment（小目标应该由高层负责，但 43px 目标在 P4 可能 <1 网格）。

### 3.3 max_det 饱和审计（服务器 GPU）
- 80 个无候选目标所在图，M1 是否达到 max_det=500 上限；
- 若饱和，看截断前的候选池里有没有该目标的低分候选。

### 3.4 对比组
- 251 个匹配车辆作为对照组（同一审计协议）；
- 71 个低分被滤作为第二对照。

## 4. 产出

- `near_miss_audit_result.json`：每个无候选目标的归因（特征无响应/NMS压/max_det截断/边界切）
- `vehicle_candidate_diagnosis.md`：结论三态
  - 主因是特征响应不足 → 支持高分辨率候选通路假设
  - 主因是后处理 → 先改后处理（提 max_det、调 NMS）
  - 主因是来源组分布 → 强化来源稳健训练

## 5. 判断标准（总纲 §5.3）

- 车辆 Recall 0.85 需净找回 ≥21 个唯一 GT；0.90 需 ≥41 个
- 增量来自 ≥3 个 source group
- ≥2/3 fold 方向一致
- 新增 FP 经对象层可控
